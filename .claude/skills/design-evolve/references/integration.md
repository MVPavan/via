# Large-set integration mechanics

Maintain a compact concept map: source file/section, maturity, affected target
sections, decision, exclusions and unresolved conflicts. The map is an evidence
artifact, not an independent task tracker. Keep durable work status in Beads.

For large files, read concept-relevant sections with enough surrounding context
to preserve invariants. Assign independent readers clear sections and require
exact source pointers; inspect consequential source text before integrating.
Multiple writers must own disjoint target files or run sequentially.

Mirror the source core layout and filename convention under the target version.
Copy untouched documents so the set remains complete. Check all forms of old
version identifiers and filenames with search; review legitimate historical
references rather than blindly replacing version numbers in technical content.

Preserve heading hierarchy, invariant identifiers, table meanings and link targets.
Distill implementation guides into design decisions only when their meaning is
clear. Comparison notes supply the selected decision and rationale; preserve full
analysis only when requested. New subsystem documents need authorized scope and
source-backed content, not invented details to fill a template.

Useful handoff fields: integrated concept, affected files, source decisions,
verification, unresolved/deferred items. A provenance/history section may reference
prior versions; the operative design must contain all its required content.
