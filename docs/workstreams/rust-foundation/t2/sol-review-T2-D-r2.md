**Verdict: SOUND WITH CHANGES.** The two original capacity leaks are addressed for valid Store state, but the deadline path has one merge blocker.

1. **Blocker 1 — addressed.** After `start_anchor` returns an identified anchor, every acquisition error, including an acquisition timeout, enters the bounded absence check. `crates/via-host/src/host.rs:389` releases its token only when the proof is `GroupAbsent` (`crates/via-host/src/host.rs:65`). An anchor that spawns but fails before identification cannot be safely probed; retaining its slot until reconciliation is acceptable.

   The extra three seconds starts after the acquisition deadline and after the pre-ARM gate, so it cannot authorize a late ARM. On force, Wire’s two-second grace can drop an unfinished proof (`crates/via-wire/src/runtime.rs:213`); the slot then remains held for shutdown reconciliation. That is conservative and does not admit another child during force shutdown.

2. **Blocker 2 — partially addressed.** The deadline count reads `anchors` directly, including intent-only rows after the cursor, and `crates/via-core/src/engine/recovery.rs:443` combines unidentified and identified groups without releasing a permit while the remaining count fills the pool. Unidentified holdings have no drop path during admission. This meets §8’s connection bound for the counted rows and preserves §7’s rule that an incomplete Host reconciliation need not fail startup.

   **Merge blocker:** “one query” is not a bounded query. The new `COUNT(*)` (`crates/via-store/src/runtime/anchor.rs:231`) scans an unbounded historical suffix, has no supporting absence index, and Core awaits it without a deadline (`crates/via-core/src/engine/recovery.rs:141`). A large inventory can therefore stall startup after the five-second reconciliation deadline, defeating the availability decision. **Fix:** add an index for unproven anchor IDs and count only up to the pool size. Because unidentified groups cannot be released during admission, a saturated count has the same permit behavior as the exact count.

   A row missing its `turns` join *after* the cursor is counted. An orphan *before* the cursor could be skipped by the joined owner page (`crates/via-store/src/runtime/anchor.rs:247`), but the Store writer enables foreign keys and requires an owning turn; I do not treat a foreign-key-violating database as a valid acquisition state. If recovery must tolerate externally corrupted Store rows, the concrete hardening is to page raw anchors and validate owners separately.

3. **Regressions:** The failed-vendor test checks both a successor completing and a committed absence proof; it detects the original retained-slot failure (`crates/via-cli/tests/s1_crash_points.rs:2485`). The deadline test places an unproven anchor beyond the first page and checks that the successor stays queued without submission; it detects the original uncounted-suffix failure (`crates/via-cli/tests/s1_crash_points.rs:2527`). The unit test detects premature permit release when identified groups disappear. None checks count-query scalability.
