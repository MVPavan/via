# T2-B2: per-session dispatch redesign (design first)

Model: Opus 5.5 high. Follow `../w1/common.md`; report to
`reports/T2-B2.md`. Takes over T2-B after three review rounds
(`sol-review-T2-B.md`, `-r2.md`, `-r3.md`, and `reports/T2-B.md`). Start
from T2-B's branch `origin/claude/t2-b-rust-foundation-juogko` (create your
session branch from it), then merge `origin/rust-foundation`.

Why: T2-B's features work (multi-turn, resume, queue, spawn retries,
`wait.timeout_ms`), but dispatch grew by patches: each drive polls its
predecessor every 250 ms, orphan receipts are reconciled only as a side
effect of other requests, and force stop is checked at scattered points.
Round 3 still found stranded committed work, a force-vs-submit race and
unbounded Store load (`sol-review-T2-B-r3.md`).

## Step 1: design note, then stop

Write `t2/dispatch-design.md` (short, normative) and push it, then reply
"design ready" and wait for the orchestrator. It must define:

- **One dispatcher per session** that owns the session's queued turns and
  every dispatch decision (run, wait, cancel), driven by events rather than
  polling: turn receipted or adopted, predecessor terminal committed,
  reconciliation result, stop/force accepted, and a bounded retry timer for
  failed Store reads (backoff, not per-turn 250 ms polls).
- **One daemon-owned orphan reconciler**: coalesced wakeups, retry with
  backoff while Store reads fail, a wake when adoption capacity returns,
  exactly-once handoff, and orphans counted toward the queued bounds
  (8/session, 128 daemon-wide).
- **Force authorization**: a turn's submission requires a dispatch grant
  checked under the same lock that accepts stop/force, so a turn still
  queued when force is accepted is cancelled without submission.
- **Stop and shutdown accounting** for orphans and waiting turns (drain
  waits for them, force cancels them, idle stop cannot skip them).
- **Bounds**: Store reads per event, memory, tasks per session; how C1
  §7.3/§7.5/§8.1 behaviour maps onto the states.

## Step 2 (after the orchestrator's go-ahead)

Implement the design on the branch, replacing the polling loop; keep the
existing T2-B tests passing and add Sol's round-3 regressions: an orphan
with no later request, a full adoption channel, stop before
reconciliation, both sides of the force read-to-submit race, and a
many-waiters/orphans load bound.
