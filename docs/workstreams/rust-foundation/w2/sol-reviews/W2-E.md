**Verdict: SOUND WITH CHANGES.** The branch carries observations through Route, Adapter and Core, retains oversized stdout for the failure drain, and preserves typed failure causes. Its tests demonstrate those main regressions. The following gaps prevent accepting the broader claims of bounded cleanup and complete C1 failure reporting.

### Findings

1. **Important — Failure cleanup can wait indefinitely on a raw append.** [via-wire/src/runtime.rs](crates/via-wire/src/runtime.rs:255) drains retained bytes and later pipe reads through `record().await` without applying the cleanup deadline. `RawWriter::append` waits for a Store worker reply without a timeout. A stalled worker can therefore prevent `drain_to_eof` from returning, despite Route’s stated three-second cleanup bound. Bound raw append waits by the same absolute cleanup deadline, latch incomplete evidence on expiry, and continue a bounded discard drain. Add a stalled-worker regression.

2. **Important — A wall-deadline result violates C1.** [via-core/src/engine.rs](crates/via-core/src/engine.rs:549) always emits `cancel: null`. C1 §7.6 requires a filled cancel outcome when Core’s deadline ends a running turn. The new deadline test checks class and stop reason but leaves this mismatch undetected. Drive the deadline cancellation path and include its evidenced outcome and cleanup certainty in the envelope; assert those fields in the end-to-end test.

3. **Important — An uncertain observation commit can strand the turn.** [via-core/src/engine.rs](crates/via-core/src/engine.rs:307) treats every `commit_event` error as an uncommitted event and retains the old sequence. [via-store/src/runtime/sql.rs](crates/via-store/src/runtime/sql.rs:414) explicitly permits an *uncertain* transaction outcome. If that event committed, the later terminal insert uses the wrong next sequence and can fail, leaving the receipted turn running. Reconcile the durable event head before terminal commit, and report C1’s `store_error` for a turn that cannot be resolved durably. The report calls this pre-existing, but this observation-commit path is new.

4. **Important — The raw-append regression does not prove the claimed end-to-end behavior.** [route_stream.rs](crates/via-core/tests/route_stream.rs:262) asserts a `Store` cause and `raw_incomplete: true`; it neither proves the later stdout and stderr were drained nor exercises Core’s `raw_log.incomplete` event and envelope warning. Add a controlled append failure through the full turn path and assert drain completion, the committed event, and the warning.

I agree that the 4 MiB observation budget and 10-second stall timer are deferred by the W2 brief, and that `vendor.other.truncated` needs a C1 contract update. The report also correctly flags the deadline cancel mismatch, but it is a current contract defect, not merely uncertainty. The oversized-line test’s **complete** raw-log expectation is sound when every byte is retained; C1 calls for incompleteness when bytes are lost.

The observation and failure-class end-to-end tests would fail on the pre-change behavior for the reported reasons.
