### Findings

1. **Important — C1 document bounds remain unenforced.** [server.rs](crates/via-cli/src/server.rs:170) builds a `serde_json::Value` before checking C1’s depth limit of 64 and node limit of 65,536. A request under the 16 MiB line cap can still exceed the node limit and consume substantially more memory while parsing. The worker correctly lists this as open. Enforce both limits before constructing the value, with boundary tests. This is an existing gap, not a regression introduced by the commit.

2. **Important — the strict DTOs preserve an incomplete contract for methods already exposed.** [api.rs](crates/via-core/src/api.rs:40) accepts only `address` for `wait` and only `session` for `events` and `logs`; [api.rs](crates/via-core/src/api.rs:61) accepts `force` but not `drain`. C1 specifies `wait.timeout_ms`, turn addresses and paging options for `events`/`logs`, and `daemon/stop.drain`. The new parser now explicitly rejects those fields as `unknown_field`. Some behavior was already absent in Core, so this is not solely W1-B’s defect; the worker’s open-item list identifies it but understates its effect on methods that exist today. Complete the DTO and owning-layer behavior in the relevant slices, and test both the accepted parameter and its effect.

3. **Minor — the client wiring regression silently passes on ordinary unprivileged runs.** [c1_protocol.rs](crates/via-cli/tests/c1_protocol.rs:388) returns success without exercising the CLI when effective uid is not root. The unit test checks `verified_peer` itself, but would still pass if its call in `request` were removed. Keep a non-skipping end-to-end path for the wiring, or make the privileged case an explicit, separately reported gate.
