**New defects introduced by the fixes**

- **Important — constructing and dropping `close()` can orphan its stop path.** State becomes closed and `active` is removed synchronously, but the stop order is posted only when the returned future is polled. Dropping it unpolled leaves the running turn without that close order and removes the sender from driver state. [driver.rs:407](../../../../../crates/via-adapters/src/driver.rs#L407)
- **Important — reservation commits before the final Adapter outcome.** A persistent logical success followed by observation-delivery overflow returns a failed turn while retaining a live pin/capacity. A dropped logical-result receiver is similarly ignored after commit. Commit/rollback must cover the Adapter’s final delivery outcome. [fake/driver.rs:422](../../../../../crates/via-adapters/src/fake/driver.rs#L422)
- **Important — control count permits nine outstanding steers.** One request can await vendor evidence while eight more occupy the channel. The command permit must remain held through resolution, as the byte permit does. [lane.rs:119](../../../../../crates/via-routes/src/fake/runtime/lane.rs#L119)
- **Important — idle close can silently lose its observation.** A live but stalled receiver makes `sink.send` fail; the idle source ignores that result and exits without latching overflow. The comment’s claim that the session channel is gone does not cover this case. [fake/driver.rs:551](../../../../../crates/via-adapters/src/fake/driver.rs#L551)
