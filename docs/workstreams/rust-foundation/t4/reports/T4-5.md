- [x] **No lock around prompt-file I/O or blob writes.** `stage_prompt`
  copies the file and writes the blob before `spawn_admitted` or

  checks and commit run; an unadopted blob is discarded after they
  return. `s1_c1_prompt_file_copies_hashes_and_refuses_changes` holds a
  copy at `prompt_file.copy.pause` and gets `close` and `daemon/status`
  replies within 100 ms.
- [x] G green; the selector is nonempty and passes.

Sol scrutiny items, where each is met:

- The slot is an `OwnedSemaphorePermit` moved into the connection task's
  future (`serving.rs` `admit`), so it is released on every exit: return,
  error, panic or abort. The shutdown diagnostic window shares the slots
  through `Client`.
- The 5 s deadline starts when the line's first byte is available
  (`read_line`); an idle connection waits with no deadline, in a `select`
  with final shutdown's `closing`.
- After `request_too_large` the task writes under 2 s and breaks without
  another read.
- Each reply is written under `timeout(REPLY_WRITE, write_all)`, so the
  timer starts before the first write.
- The streamed identity hashes the same bytes the byte-identical rule
  kept, with the handle's span replaced by its hex hash and, for a prompt
  file, the path's span by the quoted content token; duplicates and a
  span that does not match are refused.
- `copy_file` opens with `O_NONBLOCK`, `fstat`s before and after, refuses
  by reason (`not_absolute`, `unreadable`, `not_regular`, `too_large`,
  `not_utf8`, `changed`, `timeout`), and bounds the whole pass at 10 s;
  each blob step stays owned by `BlobTasks` (`run_until`).
- `close` and daemon stop never wait for a copy: the copy holds no lock,
  and final shutdown's client join is bounded and then aborts.
- `serve --stdio` connects (auto-starting the daemon without `hello`),
  checks the peer, then runs the two copies in one `JoinSet`; stdin EOF
  shuts the socket's write side; the proxy ends when the daemon side ends.

## Deviations

- **`await_terminal` reads `terminal_facts`, not `result_text`.** The plan
  and design §6.7 list it with `result`/`wait`. Its only caller, `cancel`,
  replies with `state` and `cancel`, which the facts carry, so no envelope
  is read or parsed. The plan's aim, no `Value` from the stored envelope,
  is met more directly.
- **The prompt-file copy lives in `via-store`'s `blob.rs`** (`Blobs::
  copy_file`, `PromptFileError`, `PROMPT_MAX`), outside the owned paths.
  via-core has no `rustix`, and the copy reuses `BlobTasks`' step
  ownership. `receipt.rs` calls it through `StoreClient::copy_prompt_file`.
- **Other edits outside the listed owned paths:** `via-store`
  `runtime.rs`/`sql.rs` (`SpawnRecord.label`, `QueuedTurn.cwd` via the
  session's params), `via-core` `engine.rs`, `resolve.rs`, `recovery.rs`,
  `control.rs`, `close.rs` and `journal.rs` (the `cwd` fields and the new
  signatures), `via-adapters` `runtime.rs` (`fake_cwd`).
- **The fake agent now depends on `sha2`**, an existing workspace crate,
  for `echo_prompt_digest` (one `Cargo.lock` line).
- **`vendor` emptiness** decodes a `BTreeMap<String, &RawValue>` and checks
  each value's `shape`: an object of borrowed raw values, not a `Value`.
- **CLI choices.** `--instructions F` sends `{"path": <F made absolute>}`
  (C1 §4 allows `{text}` or `{path}`). The session-scope flags
  (`--instructions`, `--cwd`, `--require`, `--allow-untested`, `--label`)
  are on `spawn` only, since C1 §3.3's `resume` CLI lists per-turn flags
  and the daemon refuses session members on `resume`; `--prompt-file` is
  on both.
- **`serve --stdio` copies with `spawn_blocking`** tasks in the `JoinSet`:
  Tokio's `io-std` feature is not enabled, and enabling it was not needed.
  A failed write to the daemon ends the stdin copy quietly; the daemon side
  ending is what ends the proxy.
- **A path over 4,096 bytes is refused `unreadable`**; the design names no
  reason for length.
- **Identity before admission.** The identity is computed at design step 6,
  before `admission`, so a handle error now comes before the
  `store_failed` check.
- **A duplicate envelope member is `invalid_request`** (it was
  `invalid_params` through `raw_params`).
- **`wait`'s check counting** in the scenario counts `store.read.delay_ms`
  hits in a window, not a paused clock (Tokio's `test-util` is not
  enabled).

## Concerns and limits

- `line_cap_includes_the_line_feed` has no RED run: it was written with the
  reader. The scenarios `s1_c1_request_too_large_is_named_then_closes` and
  `s1_f05_oversize_line_is_refused_and_closed` did fail first.
- `s1_daemon_stop_unread_reply_still_stops` can no longer fill the socket
  buffer with one reply, because the design capped the line and the id.
  The unread-and-blocked case is now `s1_c1_reply_not_read_closes_the_socket`,
  which does not exercise `daemon/stop`. The stop reply keeps its own 2 s
  bound (`STOP_REPLY`).
- The partial-line deadline starts when the connection task first sees the
  line's bytes. Bytes already buffered behind a previous request start it
  when the task turns to them, so the bound is lenient by at most one
  request's handling, never early.
- If one `wait` check takes longer than 1 s, the next checks run back to
  back until the schedule catches up; they are still one read at a time
  per waiter.
- The envelope's `cwd` is `null` for a turn recovered `unknown` and for a
  queueing rebuilt from the event history, which carries no `cwd`.
- `s1_t2d_uncertain_cleanup_keeps_its_connection_slot` was already timing
  dependent (the re-probe's first pass at 1 s); it now observes the end by
  a 20 ms `result` poll.
- The bisect check left a gitignored build directory, `target/wt-check`
  (about 500 MiB); the command hook refused a recursive delete.
