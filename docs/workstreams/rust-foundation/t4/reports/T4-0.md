## 3. Current code that contradicts a contract

Contracts win. Each item names the design section that resolves it.

1. Oversize line closes silently (`dispatch.rs:45-46`); F5 and C1 §1 want a
   request error. No socket cap, no partial-line deadline, no input budget
   (design §7.1).
2. JSON is parsed to a `Value` before any depth or node check (`dispatch.rs:48`);
   C1 §1 forbids it (design §7.2).
3. The Wire reader is the consumer's task with a per-unit ack and double sync;
   runtime §4 wants per-pipe reader tasks and batched sync. `WireParts` and
   `WireHealth` are specified or defined but unused (design §4, T4-A5).
4. `RawWriter::append` maps a full raw queue to a Store-class `Raw` error
   (`runtime.rs:529-532`); runtime §8 says raw staging overflow is `incomplete`
   plus cleanup and never pipe backpressure (design §3.3, T4-A1).
5. One 128-slot Store FIFO (`runtime.rs:1021`) versus 64 + 8 reserved lanes with
   request-side refusal (design §3.1, T4-A2).
6. No byte pool anywhere; the observation channel is 64 items; waits are
   bounded by the turn deadline, not the 10 s stall; Route is not polled during
   a delivery (`crates/via-adapters/src/runtime.rs:145-181`). C2 A1 and runtime
   §8 say otherwise (design §2, §5).
7. `events` and `logs` are non-paged and session-typed; `logs` maps every Store
   error to `store_error` (`crates/via-core/src/engine/read.rs:126-145`).
8. `daemon/status` has no `started_at`; `sessions.idle` is a constant 0 and
   `sessions.active` counts turns (`dispatch.rs:206-220`).
9. `read_either`'s doc says the cancel signal ends the wait before any byte is
   read, but its `tokio::select!` has no `biased;` and picks a ready branch at
   random (`crates/via-wire/src/runtime.rs:549-555`).
10. A nested `deadlines.*: null` is accepted (`api.rs:84-94`). C1 §1's field
    rules (`via-api-v1.md:110`) make `?` members optional-omitted and only
    nullable fields carry `null`; `deadlines.wall_ms?` and `idle_ms?`
    (`:405`) are not nullable, and T2 already refuses `bound: null` as
    `invalid_params` (`t2/README.md:22-23`).
11. The fake wall default is 30 000 ms (`api.rs:884`); C1 §4 says 3 600 000.
12. `describe` is `method_not_found` and a test asserts it (`c1_protocol.rs:238`);
    `models`, `status`, `list`, `unsubscribe`, `serve --stdio` are absent.
13. An unknown model is `invalid_params` (`receipt.rs:100`); C1 §8.1 has
    `unknown_model`. `UNKNOWN_MODEL`, `HISTORY_PRUNED` and an overload constant are absent
    from `api.rs`.
14. T3 A14's replacement text is recorded in `t3/design.md` but not yet applied
    to runtime §7; the coordinator applies it together with T4-A1 and T4-A2.
15. `runtime-contracts.md:686-695` still says "Schema v4 is exactly"; the store is at v5
    (`crates/via-store/src/runtime.rs:24`) and this design makes it v6 (T4-A8).
16. Dependencies: `tokio-util` (`Cargo.toml:14`) and `proptest` (`Cargo.toml:28`) are declared
    in the workspace but absent from `Cargo.lock` and every crate manifest, while
    coding-style §5 and §10 name them (Q5, Q6).
