## What was built

- **Store.**
  - Schema v6 matches §6.6, and `s1_store_v6.rs` freezes it.
  - `sessions` gains `created_ms`, `updated_ms`, `harness`, `label` and
    `ord`. `ord` is taken from the new `session_ord` counter.
    `vendor_session_id` and `transcript_hint` stay NULL.
  - `updated_ms` is set from the `at` of the transaction's
    highest-`seq` event.
  - `events` gains `turn` and `type`, and `at` is parsed strictly as
    `YYYY-MM-DDTHH:MM:SS.mmmZ`.
  - `turns` gains `ended_seq`, written on every terminal path, and
    `evidence_dir`, written with `turn.submitted`.
  - `prompt_blob` is NULL until T4-2.
  - `steps` is DDL only.
  - Identities are stored as `identity_len` + `identity_sha256`, and two
    identities match when both are equal.
  - `EvidenceRoot` covers `<state>/evidence`. `create_turn` makes
    `<sid>` if it is missing and `<turn>` exclusively, both 0700, and
    syncs each parent once.
  - `evidence_refs` replaces `read_logs`, and `store.read.corrupt.logs`
    now fires on it.
  - Removed: the raw worker, `raw/` validation, `StoreError::Raw` and the
    two raw failpoints.
- **Host.**
  - `PrivateProcessSpec.stderr_path`.
  - `stderr.log` is opened create_new, 0600 and `O_NOFOLLOW` before the
    anchor intent commit. A failure is `HostError::Evidence`, with nothing
    committed and nothing launched.
  - The anchor gets the file as its stderr, and the vendor inherits it.
  - `OwnedPipes` has no `stderr`.
- **Wire.**
  - `open_connection` creates the turn's folder on the blocking pool before
    Host acquisition. A failure is `WireError::Evidence`.
  - `keep_undecoded` writes the first 64 KiB (`UNDECODED_BYTES`) to
    `undecoded.bin`, create_new, 0600, on the blocking pool with a 2 s
    bound. It keeps the first note only.
  - Callers: Route on a decode failure, Wire's over-cap line
    (`MessageTooLarge`), and an unterminated stdout tail.
  - Removed: `record`, `RawEvidence`, the stderr arm, `drain_pipes` and
    `LAUNCH_DRAIN`. After-ARM pipes are dropped. `drain_to_eof` reads and
    discards stdout.
- **Route.**
  - `RouteFailure.undecoded: Option<String>` is shown as
    `"{cause}; {note}"`.
  - `MessageTooLarge` maps to `Overflow` (C1 §8.2).
  - `Evidence` and `Host(Evidence)` map to `Store{Evidence}`
    (`StoreFailure::Evidence`, non-latching; `FailureSite::Evidence`,
    kind `evidence_failed`).
- **Core.**
  - Removed: `Event.raw_ref`, `RawSpan`, `raw_spans`, `raw_log.incomplete`
    and its warning, and the recovery raw-incompleteness logic.
  - `Envelope.evidence = {folder, transcript}` comes after `events`.
    `folder` is absolute: drive computes it from the Store root, and
    recovery computes it from the address. It is null for a turn never
    submitted.
  - `logs` takes `LogsParams {session | turn}`, exactly one. A missing
    session is `session_not_found`; a missing turn is `turn_not_found`.
  - `logs` lstats `EVIDENCE_FILES` on the blocking pool, keeps regular
    files only and never opens one.
  - The uncertain-event read-back compares the whole event JSON (it
    previously compared `raw_ref`).
- **CLI.**
  - The `logs` DTO in `server/dispatch.rs`.
  - `via logs <address>` sends `turn` when the address has a `/`, and
    `session` otherwise.

## Deviations and design conflicts

- **§7.4 `transcript?` on `session.vendor_identity_confirmed`, and the
  "in-memory generation check keyed by the derived connection ID"** are not
  implemented.
  - The base has no `connections` table, no vendor identity confirmation
    and no generation check. `drive.rs:48-58` at `efe8e0b` only derived a
    connection name for raw paths.
  - So nothing exists to move, and nothing produces a vendor session ID or
    a transcript hint.
  - `sessions.vendor_session_id` and `transcript_hint` stay NULL.
  - `logs` and the envelope return `vendor_session_id: null` and
    `transcript: null`.
  - These are filled by the vendor-adapter chunks that confirm a vendor
    identity. I treat this as a plan statement with no code to act on, not
    a design conflict.
- **Edits outside the owned paths.** Each change is minimal:
  - `crates/via-host/src/lib.rs`: `PrivateProcessSpec` lives there.
  - `crates/via-cli/src/main.rs`: the `via logs` address picks `turn` or
    `session`.
  - `crates/via-cli/src/server.rs`: the daemon no longer creates
    `state/raw`, because the Store owns `evidence/`.
- **Failure kind string.** `FailureSite::Evidence` reads `evidence_failed`,
  where it read `raw_failed` before. The design names the site but not the
  string.
- **Undecoded note format.** The note reads, for example:
  `undecodable vendor message: 204800 bytes; first 65536 in <path>`.
  - Byte counts are plain digits, with no thousands separators.
  - A failed save reads `...; not saved: <error>`.
- **Pipes after ARM.** On an acquisition failure, the pipes after ARM are
  dropped, not drained. There is no raw log left to fill, and Host's close
  stops the group.
- **Wire `undecoded.bin` open** uses create_new (`O_EXCL`, which never
  follows a symlink) without `O_NOFOLLOW`. `via-wire` has no `rustix`
  dependency, and the constraints forbid adding one.

## Review round 1 fixes

Sol high round 1 found one important issue, and nothing else. Wire's
`write_new` reported `undecoded.bin` as saved after `write_all`, without
syncing the file or its folder. The failure message names that file, and
coding style §7 "Write order" requires the file to be synced with its folder
before the terminal commits.

- **Fix** (`crates/via-wire/src/runtime.rs`, `write_new`):
  - After `write_all`, the file is `sync_all`ed, then the turn's evidence
    folder is opened and synced.
  - Only then does `keep_undecoded` name the path.
  - A write or sync failure is still reported as `...; not saved: <error>`
    (design §7.3).
  - It still runs on the blocking pool under the 2 s bound. No seam was
    added.
- **Test:** the new unit test
  `runtime::undecoded_tests::a_saved_undecoded_file_is_synced_with_its_folder`
  in `via-wire`.
  - A saved file is written in full.
  - A folder that can be written but not opened (mode 0300) makes the save
    fail. Before the fix it was reported as saved; after the fix the
    folder sync fails.
- **RED:** `r1-red-undecoded-sync.log`: panics with `an unsynced folder was
  reported saved`.
- **GREEN:** `r1-green-undecoded-sync.log`.

## Review round 2 fixes

Sol high round 2 accepted the sync fix and raised two items.

1. **The sync test when run as root** (`via-wire`,
   `a_saved_undecoded_file_is_synced_with_its_folder`).
   - The problem: under CAP_DAC_OVERRIDE, mode 0300 does not stop the
     folder from being opened. The test's premise then fails, even though
     the fix works.
   - The change: after setting 0300, the test tries `File::open` on the
     folder. If that succeeds, the process bypasses file permissions, and
     only the negative assertion is skipped, with an `eprintln!` note.
     Otherwise it asserts as before.
   - The positive half (the file is saved with its bytes) still runs
     unconditionally.
   - No production seam was added.
2. **`logs` dropping files it cannot stat** (`via-core` `read.rs`,
   `evidence_files`).
   - The problem: `.ok()?` treated every `lstat` error as absent.
   - The change: `evidence_files` now returns `io::Result`. Only
     `ErrorKind::NotFound` is skipped, and non-regular files are still
     left out. Any other `lstat` error fails the `logs` call with
     `ApiError::STORE` (`store_error`).
   - Why `store_error`: it is the class the same function already uses for
     a failed `evidence_refs` read and for a failed blocking-pool join.
   - The new unit test `engine::read::tests::evidence_files_skips_only_missing_files`:
     - A folder with one `stderr.log` lists exactly that file.
     - With the folder at 0600 (no search permission), each `lstat` fails
       with EACCES, and the read must fail.
     - It uses the same skip under root.
   - RED: `r2-red-evidence-files.log`. This is a compile RED: the old
     signature returned a plain `Vec`, so the test could not observe an
     error. GREEN: `r2-green.log`.

dev-dependency that mentioned the removed raw worker, so I reworded it.
