## Acceptance checklist

- [x] `rg -n 'read_either|drain_to_eof|FakeStart|WireHealth' crates` returns
  nothing (exit 1).
- [x] The stdout reader (`connection.rs` `read_stdout`) awaits only
  `stdout.read` and the stop signal, and queues with `try_send`; it awaits
  no consumer and no Store. After a failure it awaits one bounded (2 s)
  write of `undecoded.bin` (§7.3), then discards to EOF.
- [x] Every `select!` arm in Wire, Route and the Adapter is cancel-safe:

| Site | Arm | Why cancel-safe |
|---|---|---|
| Wire `WireMessages::next_message` | `cancelled(force)`, `woken(wake)`, `latched(latch)` | `watch::Receiver::changed` loops; nothing is consumed on drop |
| | `queue.recv()` | `mpsc::Receiver::recv` is cancel-safe; byte accounting happens after it returns |
| Wire `read_stdout` | `stopped(stop)` | `watch` wait |
| | `stdout.read(&mut buffer)` | `AsyncReadExt::read` is cancel-safe (no bytes read if dropped) |
| Wire `write_stdin` | `stopped(stop)` | `watch` wait |
| | `control.recv()`, `data.recv()` | `mpsc::Receiver::recv` |
| Wire `Writing::put` | `stopped(stop)` | `watch` wait |
| | `timeout_at(deadline, stdin.write(..))` | `AsyncWriteExt::write` is cancel-safe (no bytes written if dropped); written counts are recorded only after it returns |
| Wire `runtime::open` acquisition | `cancelled(cancel)`, `&mut acquire` | the acquisition future is pinned and polled by reference; the cancel arm then awaits it with a bound |
| Route `execute` | `turn_run`, `wake_on_order` | `turn_run` is owned and polled to completion; `wake_on_order` never returns |
| Route `Serving::serve` | `forced`, `sleep_until(deadline)`, `latched`, `hop.closed()`, `woken` | `watch` waits, a timer, `Sender::closed` |
| | `pending(self.pending)` | polls the pinned `PendingWrite` by reference; it survives the other arms |
| | `hop.reserve()` | `Sender::reserve` is cancel-safe; the message stays in `held` until a permit is used |
| | `op` (`next_message`) | cancel-safe as above |
| Route stop-order waker | `sleep_until(force_at)`, `stop.changed()` | timer, `watch` |
| Adapter `execute` loop | `poll_delivery(delivery)` | polls the pinned pending delivery by reference |
| | `recv(hop_rx)` | `mpsc::Receiver::recv`; disabled while a delivery is pending |
| | `&mut route` | pinned, polled by reference |
| Adapter after Route | `forced(force)`, `rest` | `watch` wait; `rest` is dropped only under the daemon force, which ends delivery by design |
| Adapter `deliver` (no `select!`; `timeout_at` waits) | `acquire_many_owned`, `Sender::send` under the stall deadline | a dropped acquire loses no permits and a dropped `send` sends nothing; the stall deadline lives outside the waits |

## Deviations and design conflicts

1. **No proptest.** `proptest` is not in `Cargo.lock` and the brief forbids
   new dependencies; the F27 splitter property uses a seeded xorshift
   generator (200 cases, `VIA_TEST_SEED` overrides the seed).
2. **`next_message` is disabled while the start write is pending**
   (Route `Serving`). §9 lists `next_message` as arm (8) without that
   guard. Kept so that vendor messages are read only after the start is
   fully written, as the existing F10 seam `wire.prompt.after_write`
   assumes; controls (force, deadline, latch, wake) stay serviced during
   the write.
3. **`open_connection` signature** keeps today's `(spec, deadline,
   signals)`; §8.1 writes `(connection_id, evidence, spec, deadline)`.
   Since T4-1, Wire derives the turn's evidence folder from its own
   evidence root and the spec's owner, so no argument is needed.
4. **`OutboundMessage::Start`** carries a Route-provided `escape:
   fn(&str, &mut Vec<u8>)` besides `prefix`, `prompt`, `suffix`, so Wire
   streams JSON-escaped slices without knowing JSON (layer rule).
5. **A duplicate interrupt answers `NotWritten`** (coalesced, §8.3).
6. **The budget test runs at the Adapter level** in
   `crates/via-core/tests/`, not through the daemon: through the daemon a
   vendor writing more than 64 small messages in one burst fails Wire's
   queue first (concern 1), and the daemon cannot hold Core's receiver
   undrained. The daemon stall scenario covers the Core path.
7. **Edits outside the plan's owned paths:**
   `crates/via-adapters/src/lib.rs` (re-exports), `crates/via-wire/Cargo.toml`
   (tokio dev features), `crates/via-core/tests/{route_stop,route_stream}.rs`
   (updated tests above), `crates/via-core/tests/s1_observation_budget.rs`
   and `crates/via-cli/tests/s1_vendor_pipeline.rs` (new),
   `crates/via-cli/tests/support/daemon.rs` (`Daemon::start_with`),
   `crates/via-routes/tests/fake_contract.rs`,
   `scripts/check-release-features.py` (new point names and override).
   Shared with T4-2: `crates/via-core/src/engine/drive.rs` (only `execute`,
   `drain`, `while_polling`) and the export list in
   `crates/via-wire/src/lib.rs` (T4-3 replaced the export block; a merge
   with T4-2's re-export line may need a manual resolve).

## Concerns and limits

1. **Framed overflow on bursts (design Q1, accepted decision).** Wire's
   queue is 64 messages; one 64 KiB read can hold hundreds of small
   messages, which fail a healthy turn `overflow` at once. Observed: 1,040
   small lines through the daemon failed `overflow` in 241 ms, and the
   existing `force_while_forwarding_is_blocked_ends_the_turn` had to pace
   its vendor. Real vendors that burst many small events will hit this;
   T4-6's F24 flood should measure it. Revisit: split before queueing with
   a pause on read instead of failing, or a larger message count.
2. **T4-4 changes the observation set;** tests here that count
   `assistant.text` events or item costs (budget, stall, F27 daemon) will
   need T4-4 updates.
3. **Pre-existing flake** `acquisition_deadline_before_force_keeps_deadline`
   (50 ms margin between the acquisition deadline and the force; fails
   4/6 on the base under load). Not changed here.
4. **`fallback_drops()` is one process-wide counter.** Safe under nextest
   (one process per test); under `cargo test` threads, the test asserting
   exactly one drop could see another test's drop.
5. **Stall restart on acceptance** has no dedicated test that fails if the
   deadline restarts on every poll; the code keeps `stall_at` outside the
   select and clears it only after acceptance.
6. **The completed-turn path's `finish`** is not covered by a daemon
   fallback check (the three scenarios end cancelled or failed); existing
   completed-turn tests do not assert on drops.
7. After a `MessageTooLarge` the reader awaits the `undecoded.bin` write
   (at most 2 s) before discarding; the connection is already failed and
   Route is stopping the group, so the vendor blocking on a full pipe for
   that time is harmless.
