## What was built

- **Lanes (§6.1–§6.3).** `Lanes` is one `Mutex<State>` and a `Condvar`.
  - Four FIFO queues:
    - Latch: 1 request, 2 MiB.
    - Lifecycle: 7 requests, 2 MiB.
    - Internal and Public share 64 requests and 4 MiB. Public holds at
      most 32 requests of at most 4 KiB each.
  - Service order is Latch, then Lifecycle, then Internal and Public
    alternately.
  - A push never blocks. A full lane or the fence gives `NotEnqueued`. A
    dead writer gives `WriterLost`.
  - A refused command, and its reply sender with it, is dropped after the
    guard is released.
  - `DeadGuard` wraps the writer loop. On return or unwind it sets `dead`,
    drains every lane and drops the in-flight command, all outside the
    lock.
  - `Store::drop` sets the fence and joins the writer. `Command::Shutdown`
    and the `sync_channel(128)` queue are gone.
  - Handles: `StoreClient::{public, lifecycle, latch}`; the default handle
    is Internal.
- **Cap (§6.4).** `send_command` sizes each request with a counting writer
  (`encoded payload + 512`) and refuses a request over the cap as
  `NotEnqueued` before it is queued. The cap is 128 events and 1 MiB,
  excluding one terminal envelope of at most `ENVELOPE_MAX`.
  `Command::size` is an exhaustive match. A batch is sized as one request
  and is never split.
- **Full disk (§5.3).**
  - `commit_error` maps `SQLITE_FULL` to `Write`.
  - After every failed mutation, `settled()` checks
    `is_autocommit`. A connection still in a transaction gets one more
    `ROLLBACK`; if that fails, the result is `Uncertain`.
  - The seams are `store.rollback.fail` and `store.sqlite.full`. The
    latter sets `max_page_count` to the current `page_count` for one
    mutation, which produces a real `SQLITE_FULL`.
- **Terminal facts (§6.7).** `TerminalFacts { state, cancel }` is read with
  `json_extract`/`json_type`. It replaces the daemon-internal envelope
  parses in:
  - `control.rs` (cancel's already-terminal reply),
  - `journal.rs` (the read-back after an uncertain commit),
  - `stop.rs` (`unresolved_turns`),
  - `batch.rs` (`batch_reads`),
  - `drive.rs`/`recovery.rs` (predecessor decisions).
- **Public reads.** Every C1 read handler (`turns`, `result`, `wait`,
  `events`, `logs`) uses the Public handle. `ApiError::read` maps
  `NotEnqueued` to `STORE_QUEUE_FULL` (-32012, `admission_refused`) and
  anything else to `STORE`. A read error never latches.
- **Failure-resolution unit and final shutdown.** The failure-resolution
  unit runs on `latch()`. Final shutdown's calls (`stop.rs` settle,
  forced terminal, `close_forced`, `durably_open`, `unresolved_turns`,
  and `drive.rs` `finish`) run on `lifecycle()`.
- **Blobs (§6.5).** `blobs/b_<32 hex>.blob` files:
  - Each is created `create_new`, 0600, `O_NOFOLLOW`, with an id from 16
    bytes of `/dev/urandom`; `blobs/` is validated at `Store::open`.
  - `BlobWriter::write` (at most 64 KiB), `finish` (syncs the file, then
    `blobs/`), `discard` and `Drop` (unlink an unfinished file). Each step
    runs on `spawn_blocking` under 2 s.
  - `StoreClient::discard_blob` unlinks a finished blob.
    `BlobReader::next_chunk` returns at most 64 KiB. `load_text` checks
    length, SHA-256 and UTF-8; any mismatch is `CorruptEvidence`.
  - `verify_blobs` (`Corrupt("blob")`) and `sweep_blobs` run as commands
    on the SQLite thread.
  - Receipts (`receipt.rs`):
    - A prompt over `INLINE_MAX` is written and finished before
      `admission` is taken.
    - The commit adopts it (`Prompt::Blob`) when the commit succeeded or
      may have committed. Otherwise it is discarded after `admission` is
      released: on a replay, a conflict, a refusal, `NotCommitted`, or a
      `Refused` resume.
  - Dispatch (`drive.rs` `commit_submission`) loads the blob. A mismatch
    is `SubmitFailure::Corrupt`, which fails the turn as corrupt evidence
    with no agent I/O.
  - `recover()` runs `verify_blobs` and then `sweep_blobs` first.
- **JSON limits (§10.2).** `json_limits::scan` tracks string boundaries and
  escapes, and counts every value and key as a node, with a run of scalar
  bytes as one node. It fails at depth 65 or at the 65,537th node. It is
  linear in the input and does not allocate.

## Deviations and design conflicts

No design conflict was found.

- **No proptest.** `proptest` is not in `Cargo.lock`, and the brief
  forbids new dependencies. `s1_bounds_json_limits_agree_with_serde_json`
  uses a seeded xorshift generator instead. The seed comes from
  `VIA_TEST_SEED` when set, with a fixed default. It mutates documents
  over the alphabet `[]{}",:\ 0a` and compares `scan` with a serde
  `Visitor` that counts nodes, duplicate keys included. It also checks
  depth 64/65 and nodes 65,536/65,537 exactly.
- **Blob reference encoding.** Schema v6 froze `turns.prompt_blob` as one
  `TEXT` column. `BlobRef` is therefore stored as `"<id>:<len>:<sha256
  hex>"`, which gives "rows store the id" together with the length and
  SHA-256 that dispatch and `verify_blobs` check.
- **Seams added beyond the plan's list.**
  - `store.sqlite.full`: a real `SQLITE_FULL` needs a full database.
  - `store.read.corrupt.terminal_facts`: the per-read corruption point of
    the new read, following the T3-S5 pattern.
  - The test-only accessor `Lanes::fenced()`, which lets the fence test
    wait on state rather than time.
  - `store.writer.before_serve` is the plan's point. `pause` holds the
    in-flight request; `fail_io` panics the writer thread.
- **Edits outside the plan's owned paths.** Each change is minimal.
  - `via-core/src/engine/recovery.rs`: the predecessor check takes
    `TerminalFacts` (the type changed), and `recover()` runs
    `verify_blobs`/`sweep_blobs` first (§6.5 "Recovery").
  - `via-core/src/engine/tests.rs`: the one point name above.
  - `via-core/src/engine/drive.rs`: beyond `decide` and `finish`,
    `commit_submission` loads the prompt, `Submission` gains `prompt`, and
    `run` passes `prompt` to `execute` in place of `queued.prompt`. That
    is a one-token change at the call. I did not touch `execute` itself,
    which T4-3 owns.
  - `via-cli/tests/c1_protocol.rs`: one row.
- **ENOSPC** is classified only through `SQLITE_FULL`; SQLite's unix VFS
  reports ENOSPC as `SQLITE_FULL`. I added no separate errno check.

## Concerns and limits

- **Merge contact with T4-3.**
  - In `drive.rs` `run`, the `execute(... (prompt, &effective) ...)` call
    changed one token. T4-3 changes `execute`'s signature, so that call
    will conflict textually.
  - `scripts/check-release-features.py`: a separate block after
    `store.read.corrupt.anchor_records`.
  - `via-wire/src/lib.rs`: one line after `pub use via_store::StoreError;`.
- **Blocking-pool timeout.** When a blob step's 2 s bound expires, the
  `spawn_blocking` closure keeps running, because it cannot be cancelled.
  A file it then creates or leaves behind is unreferenced, so the next
  start-up's `sweep_blobs` removes it (§6.5 "a lost discard is swept").
  The same applies to a finished blob whose request future is dropped
  before `discard_unadopted` runs.
- **Blob before the refusal checks.** A large prompt is written before
  checks such as `store_failed`, `daemon_stopping` or a keyed replay, and
  is then discarded. This follows §6.5 ("written and finished before
  `admission` is taken"). It costs one write and one unlink for each
  refused large request.
- **`stage_prompt` failure** returns `receipt_not_committed` and is not
  recorded in `daemon/status` `store_failure`. §6.5 calls it
  "`not_committed` for the request", and no file is referenced.
- **The Store test RED was a compile failure** (the APIs did not exist),
  not a behavioural failure. Two tests needed corrections after their
  first run (listed under Method). For the C1 depth row, RED was obtained
  by reverting the implementation hunk.

## Review round 1 fixes

Sol high round 1 was UNSOUND on two findings, both about blob blocking
work. Every other item passed.

1. **`blocking()` left a timed-out step with no owner** (coding-style §5
   task ownership). `blob.rs` now has `BlobTasks`, which every blob
   handle shares. It is a `Mutex<JoinSet<()>>`, and the lock is never held
   across an `.await`.
   - Each step is admitted by `admit`, which first reaps ended entries
     with `try_join_next`, then runs `spawn_blocking_on` inside the set.
   - The step sends its result through a `tokio::sync::oneshot`, which
     the caller awaits under the 2 s bound. On timeout the caller gets
     `Write` (the request's `not_committed`), and the set still owns the
     step until it ends.
   - Admission is capped at `BLOB_TASKS = 16` outstanding steps. When the
     set is full, a new step is refused at once with the same
     `StoreError::Write` a failed step gives. The value covers the four
     dispatch loads (§5.1) plus a dozen concurrent receipt or discard
     steps. A healthy step is one 64 KiB write or one sync, so the cap is
     reached only when the filesystem stalls, and it bounds how many
     blocking-pool threads a stall can hold.
   - `Store::drop` joins the writer and then waits up to
     `BLOB_DRAIN = 1 s` for owned steps. That is half of final shutdown's
     2 s `STORE_RESERVE`, which the writer join shares, and it all runs
     inside the existing bounded `drop_blocking`. Any steps still running
     are reported on stderr as
     `via store: <n> blob task(s) still running at shutdown`, in the style
     of the daemon's stderr shutdown summary. No new shutdown phase was
     added.
2. **`BlobWriter::drop` unlinked synchronously on a Tokio worker.** It now
   calls `BlobTasks::unlink_detached`:
   - Inside a runtime, the unlink is an owned step.
   - At the cap, the unlink is not done, and the file is left for the
     start-up sweep (§6.5 "a lost discard is swept").
   - Outside any runtime, it unlinks synchronously.

**Seam.** `blob.step.stall` is hit inside every owned step, before its
work, and was added to `POINTS`. With `pause` it holds a blocking thread;
with `fail_io` the step fails.

**Tests.**
- `s1_blob_stalled_step_times_out_owned_until_reaped` (`s1_blob.rs`): a
  paused `blob.step.stall` makes `blob_writer()` fail `Write` after 2 s.

## Review round 2 fixes

Sol high round 2 found the shutdown path UNSOUND. Both round 1 findings
were resolved in normal operation. The problem was that a blob step still
running after the Store's 1 s drain was only written to stderr, so final
shutdown could report `clean` and exit 0 with that step still running.

1. **The drain result reaches final shutdown.**
   - `BlobTasks` is now `pub` (re-exported by via-store). Its
     `outstanding()` reaps ended steps and returns how many are still
     running. `StoreClient::blob_tasks()` and `Engine::blob_tasks()` return
     a clone of it.
   - `final_shutdown` (`via-cli/src/server/shutdown.rs`) takes that clone
     before `drop_blocking(engine, deadline)`. `Store::drop` keeps its
     bounded 1 s drain.
   - After the drop returns, final shutdown reads `outstanding()` and adds
     it to `pending_joins`, so the exit is `incomplete` (exit 4). The count
     is also reported as a new `"blob_tasks": n` member of the
     `daemon_shutdown` summary. No new phase or dependency.
2. **Store's direct stderr write is removed.** The count is reported only
   in the daemon's shutdown summary. This replaces the stderr line
   described in round 1.

**Test.** New: `s1_daemon_stop_stalled_blob_step_is_not_a_clean_exit` in
`s1_daemon_stop.rs`.
- A small turn is spawned first, so the run has turn evidence.
- A spawn with a 256 KiB + 1 prompt stalls its first blob step
  (`blob.step.stall` pause) and is refused with `store_error`,
  `commit_outcome: not_committed`.
- A plain stop follows. The test reads the summary while the step is
  still held, then releases the step and waits for the process to exit.
- It expects exit 4, `disposition: incomplete`, `blob_tasks: 1`,
  `pending_joins: 1` and `store: joined`.
- RED against round 1's code (`r2-red-stalled-shutdown.log`):
  `got exit status: 0; summary {..."disposition":"clean",..."pending_joins":0,...}`.
- GREEN: all 10 `s1_daemon_stop` tests pass.
