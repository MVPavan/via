## Outcome

- **Methods.** C1's read methods are complete and bounded: `describe`,
  `status`, `list`, `models`, and paged `events` and `logs`.
- **Encoded results.** `result` and `wait` return their envelopes as encoded
  text, through a **separate** encoded API. The `Value` result that Core's
  journal and control code consume is unchanged.
- **Charges.** Every reply is charged for its texts, its item `Vec` and its
  encoded line. A page counts the whole JSON-RPC line. No row is allocated
  before its borrowed length fits.
- **`list`.** `list` reads a fixed population and always terminates.
- **`status`.** `status` reports `alive` only on positive Host evidence, and
  `cleanup` separately (A23).
- **CLI and fixes.** The CLI gains `describe`, `status`, `list` and `models`.
  A3 and A9 are applied.

## Owning mechanisms

These are decided; do not re-choose them.

- **Pages** (§6.1).
  - `budget = 1 MiB − wrapper`, where `wrapper` is measured with the
    request's `id`. A wrapper of at least 1 MiB is refused before any read.
  - A `response` permit for `budget + 16 × limit` is taken before the read.
  - The SQLite thread creates `Vec::with_capacity(limit)`, checks each row's
    borrowed length before copying it, and stops at the first row that does
    not fit. That row is not allocated.
  - The exact reply size gets a second permit, and the reply is encoded once.
  - An item that cannot fit alone is `RESPONSE_TOO_LARGE`.
- **`events_page`** (§6.2).
  - The window is `after < seq ≤ after + 1000`, with SQL filters on the v6
    columns.
  - `next_after` stops before a row that was not returned.
  - `blocked` reports a matching row that did not fit.
  - `terminal` comes from the partial index or from `turns.ended_seq`.
- **`logs_page`** (§6.3).
  - It is joined to `connections` on `(session_id, id)`.
  - A reference is stopped before it is read when `raw_len` alone would
    overflow the budget.
  - Each reference uses one binary-search lookup, with a per-entry global
    charge of `raw_len + 3 × raw_len`.
- **`list_page`** (§6.4).
  - The cursor is `l2.<phase>.<v0>.<w0>.<k1>.<k2>`.
  - The population is `ord ≤ w0`.
  - Phase 1 is the keyset over `stamp ≤ v0`. Phase 2 examines `ord` windows
    of 1000 with `stamp > v0`, and stops at the first matching row it does not
    return.
  - The default limit is 50 and the maximum 200.
- **`session_status`** (§8.4).
  - One snapshot, read against `STATUS_BUDGET` = 1 MiB, with borrowed-length
    checks.
  - `alive` is `Engine::process_alive(unproven anchor ids)`.
  - `cleanup` is `"uncertain"` when any unproven group exists, and
    `"quiescent"` otherwise.
  - `connections` is never read for liveness.
- **`result_encoded`.** `result` and `wait` use it, with `budget =
  ENVELOPE_MAX`. `StoreClient::result` and its callers (`journal.rs:70`,
  `control.rs:210`) are untouched.
- **Lane.** Every read goes through `StoreClient::public()`.

## End-to-end test

`s1_c1_list_pages_to_completion_while_sessions_change`, through the CLI and
the daemon:

1. Create 250 sessions.
2. Page `via list --limit 50`, while another client resumes sessions and
   spawns new ones between pages.
3. Every session that existed at the first page, and that matched when its
   page was read, appears at least once.
4. No session created later appears, and the traversal ends with
   `next_cursor: null`.

It runs through `run_scenario` with `Evidence`.
