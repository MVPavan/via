## Outcome

The Store stops being one FIFO and gains the shared machinery every later
slice builds on:

- a byte pool;
- fenced request lanes with a dedicated Latch slot;
- a raw inbox with group commit, a barrier, a fault sink and a death guard
  that owns in-flight work;
- an exact command-size guard;
- the JSON counting visitor.

Core tags its shutdown handles. Nothing user-visible changes, except that
overload is now refused at the request side.

## Closes

- The carried items for Store requests (64 + 8 reserved, request-side
  refusal) and the reserved latch slot.
- The carried item that raw staging overflow is `incomplete`, not a Store
  failure. S1 lands the Store half: no `Full` case exists. S3 lands the
  reader half.
- The Store half of the carried memory item: the pool and its classes.
- The JSON depth and node limit mechanism. S5 wires it into C1 and S3 into
  Route.
- Amendments A1 (Store side) and A2.
- Decisions [t4r2.3] (both guards), [t4r2.9], [t4r2.11] (no Public byte cap),
  [t4r2.12] and [t4r2.A18] (exact guard).

## Owning mechanisms

These are decided; do not re-choose them.

- **Lanes** (design §3.1–§3.3).
  - `Store::open` creates one `Lanes` value with lanes Latch 1, Lifecycle 7,
    Internal and Public (64 ordinary, Public at most 32). Latch and Lifecycle
    share 2 MiB, ordinary requests share 6 MiB, and a Public request is at
    most 64 KiB.
  - The SQLite thread pops Latch first, then Lifecycle, then Internal and
    Public in fair round-robin.
  - `Store::drop` sets the fence, then joins.
  - `DeadGuard` holds `current` from pop to reply.
- **Raw worker** (§3.4).
  - The worker keeps `Worker{batch, current}` inside its death guard.
  - Group commit: payloads, one `sync_data`, index entries, one `sync_data`,
    then the acks.
  - Any non-`Append` command flushes the batch first.
  - The sink is called once per failed connection.
- **Lookup.** The index lookup is a binary search (§3.4).
- **`Command::bytes()`** (§3.5) is exact, measured with a counting writer. The
  cap is 128 events or `TX_PAYLOAD_MAX`. The failure-resolution batch cap is
  `EVENT_MAX + 64 KiB`; define `EVENT_MAX = (1 << 20) - (16 << 10)` in
  via-store and export it.
- **Handles.** `batch.rs` (`:85`, `:91`, `:165`) uses `latch_store`, and
  `stop.rs` uses `lifecycle_store`. H0: `finish` passes `lifecycle_store` at
  `drive.rs:1009`. `finish_with` keeps Internal.

## End-to-end test

`s1_store_lifecycle_lane_commits_when_ordinary_lanes_are_full` runs through
the real daemon:

- A running turn is started.
- The SQLite thread is held at `store.writer.before_serve`.
- The ordinary lanes are filled with Public reads, which are refused with
  `admission_refused` over C1.
- `daemon/stop` is issued and the thread is released.
- The forced terminal commits through the Lifecycle lane, and the daemon exits
  cleanly.

It runs through `run_scenario` with `Evidence`.
