# UNSOUND

Round-7’s exact-accounting findings are dissolved **as design choices**: the per-copy memory proof, SQLite growth formula, span batching, shared-connection cursor, turn holds, and per-node charge are gone. The 64-key cap and A34 precedence are fixed; the design is 1,719 lines. The replacement bounds and private `logs` path still have the failures below, so the corresponding round-7 risks are not fully resolved.

## Blocker

1. **`docs/workstreams/rust-foundation/t4/design.md:759`** — SQLite admission can pass with a 960 MiB database and an empty WAL: the admission threshold and `max_page_count` database ceiling are both 960 MiB. The next write can fail `SQLITE_FULL`, leaving no page capacity for the `failed(store)` terminal that must make a mid-turn failure visible. SQLite also does not guarantee that `SQLITE_FULL` automatically rolls back the whole transaction. **Smallest fix:** put the admission stop below the database page ceiling, protect a shared terminal/lifecycle reserve from ordinary writes, verify the configured page limit, and explicitly roll back or read back before classifying the outcome as known `NotCommitted`. [SQLite transaction behavior](https://www.sqlite.org/lang_transaction.html).

2. **`docs/workstreams/rust-foundation/t4/design.md:780`** — `WAL_MAX` is checked *after* a commit. `journal_size_limit` and a checkpoint trigger do not prevent that commit from growing the WAL past 64 MiB, so `max_page_count` plus this policy does not enforce the combined 1 GiB hard budget. A subsequent health failure detects the excess after it occurred. **Smallest fix:** bound each write’s possible WAL growth before admission, checkpoint first when needed, and refuse writes that cannot stay within the hard combined limit. [SQLite WAL behavior](https://www.sqlite.org/wal.html), [PRAGMA documentation](https://www.sqlite.org/pragma.html).

3. **`docs/workstreams/rust-foundation/t4/design.md:762`** — The raw counter has no stated increment invariant. Each append grows both a payload file and a 45-byte index entry (`crates/via-store/src/runtime/raw.rs:138`); new index headers and partial failed writes also consume space. Counting only append payloads can exceed the 3 GiB files budget. **Smallest fix:** define the counter as the sum of actual raw and blob file lengths, including indexes, headers and partial writes; reconcile it after failures and check the complete prospective growth on the raw worker.

4. **`docs/workstreams/rust-foundation/t4/design.md:514`** — The 24 MiB charge is released at drive end although it covers a connection that may remain open between turns, and `finish` may leave adopted tasks alive after its deadline (`docs/workstreams/rust-foundation/t4/design.md:917`). Retained connection buffers can then have no pool charge. **Smallest fix:** hold the connection portion until its readers, queued payloads and adopted tasks have ended; charge a per-session connection for its full lifetime.

5. **`docs/workstreams/rust-foundation/t4/design.md:1384`** — A 256 KiB *text* piece is larger than the 256 KiB **encoded observation** limit once its key and fields are added; JSON escaping can increase it further. Thus the claimed piece rule can reject valid final text as `protocol` or exceed C2’s cap. **Smallest fix:** split using the encoded size of the complete observation, including key, fields and escaping, while retaining the text-piece ceiling.

## Important

1. **`docs/workstreams/rust-foundation/t4/design.md:454`** — `r1.start` begins at offset zero even for a turn on a per-session connection whose `raw_start` is later. The cursor rule also rejects only offsets beyond the durable range, leaving offsets before the turn’s span unspecified. A turn read can include an earlier turn’s bytes. **Smallest fix:** resolve the sentinel to the selected span’s first offset and validate every supplied cursor against that span.

2. **`docs/workstreams/rust-foundation/t4/design.md:440`** — Taking `raw_start` from the *durable* end at submission does not put previously staged, undurable session traffic outside the turn: when it later commits, its offset falls inside the new span. This contradicts the author’s staged-byte claim and can misattribute a private session’s traffic. **Smallest fix:** establish and await a raw boundary before recording `raw_start`, with a rule for units already being read; test pre-submission staged traffic.

3. **`docs/workstreams/rust-foundation/t4/design.md:1597`** — The A24–A36 amendment locators and edit lists are generally precise enough to apply, but the re-grep is incomplete. Runtime §8 still requires per-copy byte permits and per-node AST charges (`docs/specs/runtime-contracts.md:1041`); Codex still calls its 16 MiB allowance a separate “global permit pool” (`docs/specs/vendors/codex.md:315`); runtime §6 still requires a checkpoint after 8 MiB WAL growth **or 1000 commits** (`docs/specs/runtime-contracts.md:769`), which §6.9 does not implement; and C1 §7.6 still says “event overflow” and “normalized-event loss” (`docs/specs/via-api-v1.md:657`). **Smallest fix:** add targeted amendments for these restatements and align the checkpoint triggers or explicitly amend that rule.

4. **`docs/workstreams/rust-foundation/t4/design.md:270`** — R3 still asks for about 95% live-token accuracy, but the design expressly withholds that claim for the three real vendors and may return `null`. R4 says crash recovery retains rows through the last completed step, while A26 narrows this to the last *committed* step (`docs/workstreams/rust-foundation/t4/requirements.md:56`, `docs/workstreams/rust-foundation/t4/requirements.md:67`). These are disclosed owner questions, but the design cannot yet claim unqualified R1–R7 conformance. **Smallest fix:** obtain the pending requirement decisions or satisfy the original wording.

## Minor

None. The SQLite cache is explicitly charged inside the 128 MiB pool, the maximal 16 MiB line’s stated charge is about **66.06 MiB**, A34’s known-failure precedence is consistent, and the 64-key cap is removed.

**Could not verify:** allocator and RSS peaks; SQLite/WAL growth under worst-case transactions; disk, crash and staged-byte failpoints; live private-connection paging; and real-vendor token accuracy. This was a read-only design review at `cf4a725`; no files changed and no implementation tests ran.
