## Method

- Failure-first, per `../w1/common.md` and coding-style §10. Before each
  behaviour change, write a regression that fails on the base for the stated
  reason; record the failing run. Label characterization tests.
- No fixed sleep as an ordering assertion. Use the §10 seams and
  acknowledgements; a sleep may only create elapsed time.
- Where the design is ambiguous, choose the reading that keeps O1's
  split: scoped when the outcome is known, latch only when it is
  uncertain. Record the choice in the report.
- Run the gate in order and stop at the first failing check. Do not pipe a
  check so that its exit status is lost. Never commit a tree that fails fmt
  or clippy; check before every commit.
