## Choices where the design was ambiguous

1. **Serving window.** Daemon main keeps accepting and serving while
   `enter_final_shutdown()` runs (the starts arm is disabled once entry
   begins). Idle expiry drops the listener first, unlinks the socket, then
   enters. This keeps S5's diagnostic window possible.
2. **Dispatcher join** (pipeline step 3) is bounded at
   `deadline − FINALIZE_RESERVE` (`Engine::dispatchers_by`), so Host
   reconciliation keeps its reserve.
3. **Resumed paging** in the re-probe loop runs only behind an
   own-groups fence: it takes every free permit and proceeds only when
   every outstanding permit is a recovered holding and no control or
   pending cleanup is live, since random anchor ids sort this daemon's
   anchors among the unread ones. Residual limit: a launch that already
   reserved a permit before the check is counted as "own" and defers the
   page to a later pass; no page is read while this daemon owns a group.
4. **Re-probe errors** from `reprobe_held` are ignored in the pass (tokens
   are kept); the row-12 latch on an uncertain proof commit is S5's.
5. **`VIA_TEST_CLIENT_VERSION`** also sets the version of a daemon the CLI
   spawns (the daemon reports `binary_version()`), so F4's replacement
   daemon matches its client.
6. **Idle re-check tick** (`IDLE_RECHECK`, 250 ms) while the predicate is
   false, because Host's pending cleanup ends without waking daemon main.
7. **Idle-only stop requests** from mismatched clients go through a bounded
   channel (8) to daemon main; a full channel is refused as "daemon not
   idle".
8. **F4 test**: after a connection drops, its client task ends
   asynchronously, so the test retries the mismatched stop on "daemon not
   idle" within a bound.
9. **Lifecycle e2e harness** follows the `s1_turn_control.rs` style
   (tempdir sandbox, direct socket, `outer_cleanup` verification) and does
   not use the `Evidence` collector: F03 and F11 cannot produce the raw
   evidence it requires.
10. **Unread recovered group, end to end**: the drain test makes one
    unread anchor with a synthetic, provable identity (pid 4195000, a pid
    above the kernel default range) behind 300 proven anchors, and pauses
    `core.recovery.page_boundary` past the 5 s startup budget.

## Design and contract edits needed

1. §6.8 entry: state the serving window (choice 1) and that idle expiry
   stops listening before entry.
2. §6.8 pipeline step 3: the dispatcher join is bounded at
   `deadline − FINALIZE_RESERVE`.
3. §6.8 / Route: once the early stop is wired, a vendor exit observed under
   the daemon force is the force row (`ForceStopped`), not `process_exited`.
4. §6.1 or runtime contract: checking an existing Store creates no
   sidecars (`immutable=1` when no `-wal` exists).
5. §8: resumed paging runs only behind the own-groups fence (choice 3),
   with its limit.
6. §10: `VIA_TEST_CLIENT_VERSION` also sets a CLI-spawned daemon's version.
7. §11, `s1_close_failed_closed_keeps_closing_count`: a pause inside
   `store.commit.closed` holds `admission`, so `daemon stop` blocks rather
   than being refused. S3's status half holds the close in its absence
   check instead (anchor paused at `host.anchor.before_eof_cleanup`). S5's
   failure half should use `fail_io`, not a pause.
8. §11, `s1_close_outcome_retained_for_late_subscriber` (force variant):
   the caller paused at `core.close.before_subscribe` is a keyed replay
   that enters after the force; the first caller, which passed the seam
   earlier, is the one that proves publication.
9. §11: the `s1_crash_points.rs` barriers count seam hits with a
   different-token command (`support/hits.rs`), because the waiters'
   hits must not pause.

## Concerns and limits

- `s1_cancel_wait_across_force_handoff` covers the main case only; its two
  variants are listed under "Deferred".
- The lifecycle e2e tests do not use the `Evidence` collector (choice 9).
- `s1_force_cutoff_worker_stalled_read_is_never_clean`'s held variant
  checks exit within 13 s of the force request (final deadline 10 s after
  entry). Under heavy load that margin is the likeliest to flake.
- The own-groups fence (choice 3) can defer resumed paging while this
  daemon keeps a group live, for as long as it does.
- Host's ledger insert drops a replaced `RecoveredGroup` token under the
  ledger mutex, which takes the `RecoveredSlots` mutex: a nested `std`
  lock, in the pre-existing order (ledger, then slots). S3's own code takes
  each alone; other slices' call sites were not audited for the reverse
  order.
