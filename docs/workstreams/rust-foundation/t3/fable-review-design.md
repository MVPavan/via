**Verdict: SOUND WITH CHANGES.** The state model, lock order and amendments are largely right and independent of the §7 policy. One disposition row asserts quiescence without proof, two races leave a caller or a close hanging, one inventory row is wrong in a way that would break a test and a contract edit, and the S3/S4 file split is not disjoint.

## Blocker

**B1. False `quiescent` for a stop before launch** (design.md:117). Row 7 says `Stopped { launched: false }` is `quiescent` "when Host's journal is complete". But `launched: false` covers the pre-ARM gate, which fires after the anchor process is spawned and `arm_intent` is committed (`crates/via-host/src/host.rs:568-595`). The anchor group exists; its absence is proved only by the failed-acquisition cleanup in `acquire_retaining` (`host.rs:397-412`), which can return `Uncertain`. Scenario: cancel while paused at `host.anchor.after_arm_intent_commit`, the anchor's EOF self-kill is slow, `wait_absence` times out, the design's row still writes `cleanup: quiescent`. That breaks runtime §5.2 ("Quiescent is committed only after the absence proof") and C1 §7.4, which limits journal-complete quiescence to "no anchor intent". Fix: row 7 reads `quiescent` only with `GroupAbsent` from the acquisition cleanup, or when no anchor intent was committed; otherwise `uncertain`. Test `s1_cancel_before_launch_launches_nothing` should assert this.

## Major

**M1. Cancel of a running turn can lose its wake** (design.md:200-213). The cancel path sends the order under slot state, then waits for the run loop to publish a durable `requested_at`. If the run loop is already past its last check of the order (inside `finish`, `crates/via-core/src/engine/drive.rs:440`) when the order lands, nothing publishes it, the terminal commits normally with `cancel: null`, and the caller waits until the daemon finalizes. Fix: the run loop drops the per-turn watch sender when it exits; the cancel path selects on the watch or that drop, and on drop reads the terminal and replies `already_terminal: true` with the envelope's `cancel`.

**M2. `close` never reaches a `Claimed` turn** (design.md:247, 149-173). Step 7 sends the stop order only to "a running turn", and the dispatcher handles a close order only "before any decision". A turn already `Claimed` (waiting in `reserve_connection`, `drive.rs:186`, then granted and submitted) launches and runs to its terminal before the dispatcher sees the order. A graceful close with `deadline_ms: 10000` then waits an entire turn, and C1 §3.6 "cancels the active turn" is not met. Fix: close attaches its order to a `Claimed` turn exactly as §3.1 does for cancel, and the claim step refuses (drops the permit, decides again) when a close order exists.

**M3. Idle deadline reclassified as `deadline_wall`** (design.md:101-102, 116). When `force_at` for an idle order equals the wall deadline, Route reports `Deadline` and row 6 gives `failed(deadline_wall)`, although the idle deadline fired first and is the cause of the stop. Scenario: `idle_ms: 2000, wall_ms: 5000`, the fake hangs after acceptance; idle fires at +2 s with `force_at = +5 s = wall`; result `deadline_wall`. The class is untruthful and F19's idle test cannot shorten its 10 s hard-coded grace without hitting it. Fix: the stop order's cause decides the class when Route's `Deadline` coincides with an order's `force_at`; `Deadline` with no order stays `deadline_wall`.

**M4. F23 inventory and contradiction 9 are wrong** (reports/T3-0.md:39, 124-129; design.md:663). Host refuses a caller-supplied marker but then adds its own random `VIA_PROCESS_MARKER` to the vendor environment (`host.rs:572`). So runtime §5's "vendor VIA marker" is correct and must not be deleted, and `s1_f23_agent_sees_only_allow_listed_env` must expect the allow list plus that marker. Fix: reverse recommendation 9; the test asserts the two fake keys plus a `VIA_PROCESS_MARKER` whose value is not the anchor's marker.

**M5. S3 and S4 are not disjoint** (design.md:698-699). S3's re-probe loop must split `RecoveredSlots.groups` into identified and recomputed-unidentified counts and resume from `reconcile`'s saved cursor; both live in `crates/via-core/src/engine/recovery.rs:136-190, 421-470`, which S4 owns. Fix: S0 also moves `RecoveredSlots` and the reconciliation cursor into `engine/slots.rs` (S3-owned), or S4 runs after S3.

**M6. Force's idle-session pass makes exit 0 unattainable at scale** (design.md:358-371). Every open historical session is closed on each `daemon stop --force`, one transaction per 128, and a pass cut off by the 10 s deadline counts in `unclosed_sessions` (exit 4). With a few thousand sessions on disk, force is never clean and every idle session becomes unresumable. This is a literal reading of C1 §3.14 and the carried item, so it needs the owner. Recommended fix: scope the pass to sessions that held dispatch state during this daemon's lifetime (a bounded set the Engine already tracks through `sessions`, extended to remember retired ones), and list the "every session on disk" reading as a rejected alternative.

## Minor

- **Idle predicate location** (design.md:341-344 vs 375): §6.4 says only daemon main evaluates the predicate, but §6.2 needs it inside the `hello` handler, and `request_stop` checks `active()` only, not clients. Fix: the handler asks daemon main (a request on the existing stop `Notify` path) to stop-if-idle-minus-this-client and returns its answer.
- **Double `cancel.requested`** (design.md:55-56, 77): the wall deadline "keeps its current path", which commits `CancelRequested` after Route returns (`drive.rs:428`); a cancel order already committed one. Fix: the deadline path skips the commit when an order committed it and keeps that order's `requested_at`.
- **Re-probe stops at stop acceptance** (design.md:539-540): a drain can run for hours while held slots never return, so drained turns waiting for a slot may never run. Fix: stop re-probing at final shutdown, force or the latch only.
- **Wait for `Cancelling` entries under force** (design.md:276-277): a cancel whose commit failed keeps its entry `Cancelling` forever; `force_queue`'s wait must also end on the latch, not only the read cutoff. Fix: state the wake set (pop, rollback, latch, cutoff).
- **Refused `Closed` commit is undefined** (design.md:264-265): Store's refusal is "not a failure", but the design gives the close waiter no reply and leaves the slot with a close order. Fix: reply `store_error`-free named refusal (`admission_refused`), keep `closing` durable for the restart to finish.
- **Transient read failure returns an affected-turn `store_error`** (design.md:189-190): `durable_state: queued` with `terminal_persisted: false` claims an affected turn for a one-off read miss. Fix: plain `store_error` without the turn fields, or one retry.
- **§14 independence claim** (design.md:723): §2, §3.2 and §4 each contain "latch" steps that would change under the alternative policy; §14's own bullet list admits it. Fix: say the latch calls inside §2–§4 become per-turn health marks.
- **S1 gate-green** (design.md:696): adding a stop watch to `AdapterRuntime::execute` and a `Stopped` route error breaks `drive.rs:373` and `terminal.rs:90-98` compile. Fix: grant S1 a narrow allowance to touch those two call sites, or make the additions additive.
- **Runtime §3 `interrupt` method** (design.md:70-71, runtime-contracts.md:136): C3 lists `FakeRoute::interrupt(deadline)`; the design delivers cancel through a watch. Fix: list as an amendment or state that `execute` supersedes C3's split entrypoints.
- **S4 effort** (design.md:699): F22 positive proofs and identity negatives are recovery and identity work, which t0.md:66 assigns to high. Fix: S4 high.
- **"Each test must first fail"** (design.md:624-625): `s1_f02_`, `s1_f09_` without the warning, and `s1_f22_autonomous_eof_` pass on current code. Fix: mark them characterization scenarios.
- **Determinism seams missing** (design.md:646, 649, 650): F1's "loser exits 75" needs a startup pause after `daemon.lock`; F4 needs a test-build client-version override to run through the real binary; F6's "client during final shutdown" needs a pause in idle final shutdown. Fix: add three `test-failpoints` seams to §10.

Amendments A1–A8 are otherwise necessary and consistent with C1 and runtime; A2 could be avoided by committing `Closed` directly under admission for an idle session, but the uniform path is acceptable. Inventory rows other than F23 match the code I read.
