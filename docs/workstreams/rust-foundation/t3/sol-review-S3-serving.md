## Verdict: SOUND WITH CHANGES

The serving and shutdown paths mostly follow the S3 design, but three issues need changes before I would accept this part.

### Findings

1. **Important — resumed recovery can starve while a current group remains live.** `wt/t3-s3:crates/via-core/src/engine/reprobe.rs:139–154` refuses every resumed page whenever this daemon owns a group. That avoids probing one of its own randomly ordered anchors, but a long-lived group can keep an older daemon’s unread anchors unexamined indefinitely. Their permits can then block a queued turn, including during drain. The one-slot drain test exercises only the case with no current group. **Fix:** identify the startup recovery cohort, or explicitly exclude this daemon’s anchors from resumed reconciliation, so pages can progress safely while current groups exist.

2. **Important — the 15-second auto-start budget does not bound `hello`.** `wt/t3-s3:crates/via-cli/src/client.rs:330–350` gives the handshake the request’s `read` timeout, which is 30 seconds for ordinary calls and can be longer for `wait`. A connected socket that does not answer `hello` can therefore exceed the single startup budget. **Fix:** bound each pre-hello read by the remaining startup budget and retry eligible reset/EOF failures only within that budget.

3. **Important — the Store probe is not an untouched, race-safe probe in every stated case.** `wt/t3-s3:crates/via-store/src/runtime.rs:826–843` chooses ordinary read-only opening when `-wal` exists; if `-shm` is missing, SQLite may create it in the State directory. The F11 test at `s1_lifecycle.rs:670–715` does not cover that sidecar state. With no `-wal`, `immutable=1` avoids sidecars, but it disables SQLite locking and change detection: it is safe only while every writer obeys VIA’s held `store.lock`. A writer outside that convention, or a WAL appearing between the existence check and open, can make the probe read inconsistent data. SQLite documents both [the immutable assumption](https://www.sqlite.org/uri.html) and [the read-only WAL sidecar conditions](https://www.sqlite.org/wal.html). **Fix:** define and enforce the probe’s writer-exclusion boundary, and add an F11 case with an existing WAL and absent SHM; use a probe method that cannot mutate the State directory for that case.

4. **Minor — adding a holding does not reliably reset re-probe backoff.** `wt/t3-s3:crates/via-core/src/engine/reprobe.rs:49–66` observes additions only at loop boundaries, then assigns `known` after a pass. An addition during a 10-second wait or pass can miss the promised 1-second reset. **Fix:** signal a holding-generation change to the loop and reset its timer when that generation advances.

### Requested checks

- **Startup and F4:** `daemon.lock` precedes `store.lock`, State and socket mutations follow both locks, stale socket replacement follows locking, and daemon-lock contention returns 75. The CLI validates an existing runtime directory before connecting. Version mismatch supplies daemon version and Store path; a mismatched connection accepts only plain stop, which daemon main evaluates with the requester excluded. The reported retry for the test’s asynchronous client exit is reasonable. The auto-start budget and Store-probe limits are above.
- **Idle and Ctrl-C:** The idle predicate includes clients, active turns, dispatchers, the durable closing set, starts, and Host pending cleanup; recovered holdings alone do not block exit. The 250 ms tick covers cleanup ending without a wake. Idle expiry rechecks, polls one pending accept, then leaves serving; `serve_bound` drops the listener and unlinks the socket before final-shutdown entry. Foreground `spawn` and `wait` install SIGINT handling that flushes stdout and exits 130; the spawned daemon has its own process group.
- **Status:** `sessions.closing` comes from the durable closing set. `connections.in_use` counts permits out; `held_unproven` counts recovered permits plus Host-held permits not already represented there. The unchanged `sessions.idle: 0` belongs to the later slice described by the design.
- **Re-probe and S4:** The loop continues through drain and returns on force, latch, or final-shutdown entry; final shutdown joins it. Identified groups use `reprobe_held`; unidentified groups use resumed paging. The own-groups fence is a valid safety precaution but lacks liveness as described above. S4’s `recovery.rs` still takes a recovered token and releases its `RecoveredSlots` guard before calling `hold_capacity`, so its new recovery edits do not introduce a reverse lock order.

The nesting nevertheless conflicts with design §1’s “never nested” rule. Move replacement-token destruction outside the ledger guard to restore that invariant.

The lifecycle tests use seam acknowledgements and observable results for ordering; the 5.2-second pause creates elapsed recovery time. The tests do not cover the mixed own-group/unread-anchor case, the WAL-without-SHM probe, or a silent pre-hello peer.
