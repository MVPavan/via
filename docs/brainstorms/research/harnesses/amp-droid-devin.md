## Amp

**Identity and distribution.** Amp is Sourcegraph’s coding agent. Its CLI executable is `amp`; install with `npm install -g @ampcode/cli` or the official installer. The npm page currently lists version `0.0.1790176630-gcb0885`, published about 31 minutes before it was crawled on Sep 24, 2026. The package page says “SEE LICENSE IN LICENSE.md”; I could not confirm the CLI’s license or find its core source repo, so OSS status is **UNVERIFIED**. [Amp install docs](https://ampcode.com/docs/cli), [npm package](https://www.npmjs.com/package/%40ampcode/cli), [npm organization](https://www.npmjs.com/org/ampcode)

**Tier and credentials.** Tier 2: Amp can route among its own model service, provider keys, subscriptions, and model routers. The docs list API-key connections including Anthropic, Meta AI, OpenAI and xAI; ChatGPT and X/Grok subscriptions; and gateways including OpenRouter and Vercel AI Gateway. [Model routing](https://ampcode.com/docs/customize/model-routing), [pricing and subscription support](https://ampcode.com/docs/pricing)

**CLI and programmatic control.** `amp -x "prompt"` runs a turn and exits. `--stream-json` emits JSONL events; the documented result includes `session_id`, `usage`, final text, and an error flag. `--stream-json-input` accepts structured input on stdin, and `amp threads continue -x ...` continues a thread across invocations. Modes include `low`, `medium`, `high`, and `ultra`; model and effort can be tuned through Amp’s settings. The CLI can serve headless runners with `amp --no-tui`. A numeric process exit-code contract, explicit noninteractive permission flags, and reliable TTY-free behavior beyond documented execute mode are **UNVERIFIED**. [Execute mode](https://ampcode.com/docs/cli/execute-mode), [streaming JSON](https://ampcode.com/news/streaming-json), [models and modes](https://ampcode.com/docs/models-and-subagents), [runner mode](https://ampcode.com/docs/cli/runners)

Amp also publishes a TypeScript/Python SDK with streaming, multi-turn continuation, settings, and MCP configuration. Its own CLI supports MCP servers; the SDK is an additional surface, not an ACP implementation. [Amp SDK](https://ampcode.com/docs/sdk), [MCP/tool docs](https://ampcode.com/docs/tools)

**ACP and maturity.** No vendor ACP was found. The ACP registry entry you supplied points to the community `tao12345666333/amp-acp` adapter, launched with `npx -y amp-acp` (or its platform binary). It streams messages and tools, supports session load/resume, and exposes permission and Amp-mode options; the adapter documents a distinct ACP session ID and durable Amp thread ID. It is Apache-2.0 and has 93 GitHub stars and 123 commits. The registry/adapter is not evidence of vendor maintenance; an adapter release cadence is **UNVERIFIED**. [Adapter repo and README](https://github.com/tao12345666333/amp-acp), [ACP registry](https://github.com/agentclientprotocol/registry)

**VIA:** Worth supporting in **v0** via CLI: the stream format already exposes the session, final result, and token usage. The community adapter is a workable alternate route where ACP is needed.

## Factory Droid

**Identity and distribution.** Product name: Factory Droid. Executable: `droid`. Install through Factory’s CLI installer, npm, or Homebrew. The supplied ACP registry entry says `0.226.2`; Factory’s stable changelog lists `0.226.1` as latest on Sep 24, 2026. This version discrepancy is **UNVERIFIED** as to channel or cause. The registry labels the agent proprietary; no public vendor CLI source repo was found. [CLI install/reference](https://docs.factory.ai/droid-cli/cli-reference), [Factory release notes](https://docs.factory.ai/changelog/release-notes), [ACP registry](https://github.com/agentclientprotocol/registry)

**Tier and credentials.** Tier 2: Factory offers models from Anthropic, OpenAI, Google, and other providers, plus custom models through BYOK. Custom model examples cover OpenAI, Anthropic, Gemini and compatible endpoints. Headless install docs require a Factory API key; personal CLI login is also available. The reviewed docs describe custom provider API keys, not login with ChatGPT/Claude subscriptions; that subscription path is **UNVERIFIED**. [Available models](https://docs.factory.ai/models), [custom models/BYOK](https://docs.factory.ai/model-independence/byok), [headless setup](https://docs.factory.ai/droid-exec/overview)

**CLI and programmatic control.** `droid exec "prompt"` is noninteractive. Output formats are `text`, `json`, and `stream-jsonrpc`; JSON includes a result, error/success state, duration, turns and session ID. `--session-id` continues an existing session. `--model` and `--reasoning-effort` select model and effort; `--auto low|medium|high` controls autonomy, with `--skip-permissions-unsafe` available as an explicitly unsafe bypass. JSON’s documented result does not show usage/cost; stream-JSON-RPC session notifications include token usage, and nonzero exit on permission violations is documented. Multi-turn input and steering are supported through RPC methods including `droid.add_user_message`; cancellation and loading a session are also available there. [Droid Exec](https://docs.factory.ai/droid-exec/overview)

Factory also provides TypeScript and Python SDKs with persistent sessions, resume, streaming, interruption, permissions and MCP support. [TypeScript SDK](https://docs.factory.ai/sdk/typescript), [Python SDK](https://docs.factory.ai/sdk/python)

**ACP and maturity.** Native ACP is documented; Factory’s IDE setup launches `droid exec --output-format acp`. The supplied registry points to `npx droid exec --output-format acp-daemon`. Factory release notes describe ACP daemon mode, persistent background sessions and session loading. Its newer `stream-jsonrpc` interface exposes session initialization/loading, messages, permission and ask-user requests, notifications, and controls. No current blocking ACP bug was confirmed in the reviewed sources. [ACP IDE integration](https://docs.factory.ai/ide-integrations), [release notes](https://docs.factory.ai/changelog/release-notes), [Droid Exec/RPC](https://docs.factory.ai/droid-exec/overview)

**Activity.** Actively maintained: Factory’s changelog reports 226 releases and a Sep 24, 2026 CLI release. The stable changelog’s `0.226.1` differs from the supplied registry `0.226.2`; recheck the exact install channel before pinning. [Release notes](https://docs.factory.ai/changelog/release-notes)

**VIA:** Worth supporting in **v0/v1**. Use JSON CLI for simple spawn/result calls; use native ACP or RPC when VIA needs mid-turn input, cancellation, resume, or permission handling.

## Devin CLI

**Identity and distribution.** Product name: Devin CLI, also called Devin for Terminal, by Cognition. Executable: `devin`. Install with `curl -fsSL https://cli.devin.ai/install.sh | bash`, Homebrew, or the Windows installer. Stable version `3000.11.3` is dated Sep 22, 2026. `CognitionAI/devin-cli` is public but has only 3 stars and exposes a README/install pointer; the distributed CLI is proprietary per the supplied registry. [CLI quickstart](https://docs.devin.ai/cli), [stable changelog](https://docs.devin.ai/cli/changelog/stable), [public repo](https://github.com/CognitionAI/devin-cli), [ACP registry](https://github.com/agentclientprotocol/registry)

**Tier and credentials.** Tier 1 classification as described above: the CLI authenticates to a Devin account, and available models can be governed by account/organization. Devin documents model families from Anthropic, OpenAI, Google and Cognition, plus open models including DeepSeek, Kimi and GLM. It supports account login, not a documented bring-your-own-provider-key or Claude/ChatGPT subscription flow. [Models](https://docs.devin.ai/cli/models), [CLI login and account distinction](https://docs.devin.ai/cli/reference/commands)

**CLI and programmatic control.** `devin -p "prompt"` prints a response and exits. The CLI documents `--export` to save an ATIF conversation, but its `-p` result is not documented as JSON with structured usage, status or exit-code fields; those contracts are **UNVERIFIED**. `--model`, permission modes, and `--sandbox` are available. Sessions can be resumed by ID with `devin --resume <id>`; single-turn resume behavior and prompt streaming over stdin are **UNVERIFIED**. Noninteractive `-p` cannot display a workspace-trust dialog and fails in untrusted directories unless trust checking is disabled. [Commands and flags](https://docs.devin.ai/cli/reference/commands), [essential commands and permissions](https://docs.devin.ai/cli/essential-commands)

**Other programmatic surfaces and cloud distinction.** Devin CLI provides an MCP client, but I found no local CLI SDK or local MCP-server mode; SDK/MCP-server availability is **UNVERIFIED**. The separate Devin Cloud API creates remote sessions using organization API keys at `/v3/organizations/{org_id}/sessions`; that is not the local CLI contract. CLI `--cloud` is a separate cloud-session mode, distinct from the local agent. [MCP and command reference](https://docs.devin.ai/cli/reference/commands), [Devin API authentication and session creation](https://docs.devin.ai/es/api-reference/authentication), [local CLI vs cloud Devin](https://docs.devin.ai/cli)

**ACP and maturity.** Native ACP: `devin acp`, launched as an ACP client’s stdio JSON-RPC subprocess. Stable release notes say the command is enabled on stable builds; recent notes include model, effort and speed controls through ACP session configuration, persistence/resume, usage totals, cancellation/revert behavior, and MCP supplied at session creation or load. The changelog also records ACP bug fixes, including persistence/resume consistency and handling channel-close errors, so version-pin and recheck known fixes when integrating. [ACP/Zed setup and limitations](https://docs.devin.ai/cli/acp/zed), [stable changelog](https://docs.devin.ai/cli/changelog/stable)

**Activity.** Actively maintained: the official stable changelog dates v3000.11.3 to Sep 22, 2026. The small GitHub repo is not representative of the proprietary CLI’s maturity; it has 3 stars. [Stable changelog](https://docs.devin.ai/cli/changelog/stable), [GitHub repo](https://github.com/CognitionAI/devin-cli)

**VIA:** Worth supporting in **v1** via native ACP. The local `-p` mode lacks a confirmed structured output contract for VIA’s result envelope, while ACP provides session lifecycle and streaming controls.
