# Cursor CLI (`cursor-agent`) research

**Research checked 2026-09-24.** Cursor CLI is not installed in this environment, so I could not obtain its installed version or run `--help`. Its documented CLI name is `agent`; the ACP registry packages the binary as `cursor-agent`. I did not run any prompts.

## 1. Identity

- **Vendor and license:** Cursor is Anysphere’s proprietary coding agent. The ACP registry labels Cursor’s CLI **proprietary**. [Cursor ACP registry entry](https://raw.githubusercontent.com/agentclientprotocol/registry/main/cursor/agent.json) (version `2026.09.18`, checked 2026-09-24).
- **Install:** Cursor documents `curl https://cursor.com/install -fsS | bash` for macOS, Linux, and WSL, and a PowerShell installer for Windows. [CLI installation](https://cursor.com/docs/cli/installation) (checked 2026-09-24).
- **Current version:** The latest version I could confirm is **`2026.09.18`**, from the ACP registry’s current Cursor entry. This is a registry version, not a locally installed version. [ACP registry entry](https://raw.githubusercontent.com/agentclientprotocol/registry/main/cursor/agent.json) (version `2026.09.18`, checked 2026-09-24).
- **Cadence:** Cursor’s CLI changelog lists a release on August 26, 2026, and the registry lists a September 18, 2026 build. That suggests frequent updates, but **UNVERIFIED:** Cursor does not promise a fixed release schedule. [CLI changelog](https://cursor.com/docs/cli/changelog) (checked 2026-09-24); [ACP registry entry](https://raw.githubusercontent.com/agentclientprotocol/registry/main/cursor/agent.json) (checked 2026-09-24).

## 2. Auth and billing

- **Authentication:** CLI supports browser login (`agent login`) and a user API key via `--api-key` or `CURSOR_API_KEY`. ACP docs also name `cursor_login` and say users can pre-authenticate using CLI login or an API key. [CLI authentication](https://cursor.com/docs/cli/reference/authentication) (checked 2026-09-24); [Cursor ACP docs](https://cursor.com/docs/cli/acp) (checked 2026-09-24).
- **Billing:** Cursor says CLI and SDK usage is billed according to the account’s model usage and pricing. The SDK accepts user and service-account API keys; its usage appears under the SDK tag in the account dashboard. [Cursor Python SDK](https://cursor.com/docs/sdk/python) (checked 2026-09-24); [Models and pricing](https://cursor.com/docs/models-and-pricing) (checked 2026-09-24).
- **Terms conflict:** Cursor documents headless CLI use for scripts and CI. But its AUP, which says it applies “regardless of subscription tier or how the Service is accessed,” lists “Accessing the Service through automated or non-human means, whether through a bot, script, or otherwise” as unacceptable conduct. The AUP does not state a CLI or SDK exception. **Conclusion: public sources do not establish that VIA’s automated use on a personal subscription is permitted.** [Headless CLI docs](https://cursor.com/docs/cli/headless) (checked 2026-09-24); [Acceptable Use Policy](https://prod.cursor.com/en-US/acceptable-use-policy) (last updated August 11, 2026).
- **Practical implication:** Do not describe personal-subscription automation as terms-approved based only on the headless docs; the AUP wording conflicts with them. Cursor should clarify this for VIA’s use case.

## 3. Headless CLI contract

- **Invocation:** `cursor-agent -p "prompt"` (Cursor docs use `agent -p`). `-p`/`--print` is documented for non-interactive scripting and CI. Cursor says print mode can use the agent’s tools, including write and shell. [CLI parameters](https://cursor.com/docs/cli/reference/parameters) (checked 2026-09-24); [Headless CLI docs](https://cursor.com/docs/cli/headless) (checked 2026-09-24).
- **Formats:** `--output-format text|json|stream-json`. Current reference says default is **text**; older Cursor reference pages report `stream-json`, so pin versions and do not trust stale docs. `--stream-partial-output` enables text deltas with `stream-json`. [Current output-format reference](https://cursor.com/docs/cli/reference/output-format) (checked 2026-09-24); [older reference](https://docs.cursor.com/en/cli/reference/output-format) (crawled about 1.1 years ago).
- **JSON result:** On success, one object contains `type: "result"`, `subtype: "success"`, `is_error: false`, `duration_ms`, `duration_api_ms`, `result` (final assistant text), `session_id`, and optional `request_id`. On failure, the process exits nonzero and writes an error to stderr; the docs say no valid result JSON is emitted. [Output-format reference](https://cursor.com/docs/cli/reference/output-format) (checked 2026-09-24).
- **Stream events:** NDJSON has `system/init` (includes cwd, session ID, model, permission mode, API-key source), user, assistant, tool-call start/completion, and terminal result events. Errors go to stderr; failure may end without a terminal result event. Consumers should ignore unknown added fields. [Output-format reference](https://cursor.com/docs/cli/reference/output-format) (checked 2026-09-24).
- **Text mode:** Prints only the final assistant message, without intermediate progress or tool summaries. [Output-format reference](https://cursor.com/docs/cli/reference/output-format) (checked 2026-09-24).
- **Usage, cost, errors and exit codes:** CLI result schemas do not document token counts or cost. Failures are nonzero with stderr text, but exact exit-code meanings are **UNVERIFIED**. The official SDK does expose token usage and billed cost; see §5. [CLI output schema](https://cursor.com/docs/cli/reference/output-format) (checked 2026-09-24); [Python SDK usage](https://cursor.com/docs/sdk/python) (checked 2026-09-24).
- **Model and effort:** `--model <model>` selects a model; `agent models` lists account-available models. CLI docs expose no general reasoning-effort flag. **UNVERIFIED:** per-model effort flags/config may exist outside the documented interface. [CLI parameters](https://cursor.com/docs/cli/reference/parameters) (checked 2026-09-24).
- **Role and prompt:** The positional prompt is supported. The CLI reference documents no direct system-prompt or role-profile flag. Project context can come from Cursor rules; Cursor also documents reading root `AGENTS.md` and `CLAUDE.md`. `--plugin-dir` loads local plugins, but is not documented as a role-prompt injection interface. [CLI parameters](https://cursor.com/docs/cli/reference/parameters) (checked 2026-09-24); [CLI usage](https://docs.cursor.com/en/cli/using) (crawled about 1.1 years ago).
- **Modes and permissions:** `--mode plan|ask` selects those modes; agent is the default. `--force`/`--yolo` allow commands unless denied. `--sandbox enabled|disabled` controls sandbox mode. The CLI also supports `--approve-mcps`, `--trust` (headless only), and workspace selection via `--workspace`. [CLI parameters](https://cursor.com/docs/cli/reference/parameters) (checked 2026-09-24).
- **Working directory / extra dirs:** `--workspace <path>` sets the workspace. The CLI parameter reference lists no `--add-dir`; ACP and SDK have multi-root mechanisms, though Cursor’s ACP page does not document additional directories. [CLI parameters](https://cursor.com/docs/cli/reference/parameters) (checked 2026-09-24); [ACP session setup](https://agentclientprotocol.com/protocol/v1/session-setup) (checked 2026-09-24); [Python SDK](https://cursor.com/docs/sdk/python) (checked 2026-09-24).
- **Trust, prompts and stdin:** `--trust` exists to avoid a headless workspace-trust prompt; ACP permission requests can block if the client does not answer. The output docs mention print mode can be inferred from piped stdin, but do not clearly specify whether stdin supplies the prompt. **UNVERIFIED:** exact stdin-prompt behavior. [CLI parameters](https://cursor.com/docs/cli/reference/parameters) (checked 2026-09-24); [ACP docs](https://cursor.com/docs/cli/acp) (checked 2026-09-24); [output-format reference](https://cursor.com/docs/cli/reference/output-format) (checked 2026-09-24).
- **Structured output and timeout:** No documented `--json-schema`/schema-constrained output flag or timeout option. **UNVERIFIED:** undocumented flags may exist.

## 4. Session lifecycle in the CLI

- **Resume:** `--resume [chatId]` resumes a specific chat; `--continue` aliases `--resume=-1`; `agent resume` resumes the latest chat; `agent ls` lists chats. [CLI parameters](https://cursor.com/docs/cli/reference/parameters) (checked 2026-09-24).
- **Fork:** **UNVERIFIED:** no CLI fork option found in the current parameter reference.
- **Persistence/background:** The August 26, 2026 changelog adds `agent persist`, `agent persist attach`, `agent persist list|stop`, and `agent persist --resume` for sessions that survive disconnects. This is documented as a persistent-session feature, not a structured VIA envelope. [CLI changelog](https://cursor.com/docs/cli/changelog) (August 26, 2026).
- **Storage and invalid IDs:** **UNVERIFIED:** official CLI docs reviewed do not specify the session storage path or the behavior when a supplied session ID is invalid. Do not silently fall back to a new session without a contract test.
- **Cancel and steer:** The CLI docs do not document a headless mid-turn input channel. Interactive Cursor has steering controls, but that does not establish a CLI/API steering contract. ACP documents `session/cancel`; it does not document a mid-turn steer operation. [CLI parameters](https://cursor.com/docs/cli/reference/parameters) (checked 2026-09-24); [Cursor ACP docs](https://cursor.com/docs/cli/acp) (checked 2026-09-24).
- **Signals:** **UNVERIFIED:** exact signal handling and clean-shutdown guarantees are not in the reviewed vendor docs.

## 5. Other programmatic surfaces

- **Official SDKs:** Cursor publishes TypeScript and Python SDKs for local and cloud agents. Local agents run against disk; the SDK has durable agent/run state, streaming messages, `wait()`, `cancel()`, `resume()`, status, message history, token counts, and billed-usage lookup. That is materially richer than the documented CLI result envelope. [Python SDK](https://cursor.com/docs/sdk/python) (checked 2026-09-24); [TypeScript SDK](https://cursor.com/docs/sdk/typescript) (checked 2026-09-24).
- **Auth and costs:** SDK uses `CURSOR_API_KEY` or an API key argument; it does not document using an existing browser-login session as its SDK credential. Billing follows Cursor pricing, and `get_usage()` returns usage and cost after settlement. [Python SDK](https://cursor.com/docs/sdk/python) (checked 2026-09-24).
- **Bridge:** Cursor documents a local SDK bridge and version/capability discovery. It supports the published SDK protocol and bridge binaries; it is an SDK transport surface, not a general CLI app-server for VIA to assume stable without pinning. [SDK Bridge](https://prod.cursor.com/docs/sdk/bridge) (checked 2026-09-24).
- **ACP:** `agent acp` is a native stdio JSON-RPC server; details in §6. [Cursor ACP docs](https://cursor.com/docs/cli/acp) (checked 2026-09-24).
- **MCP:** CLI has MCP server management, but MCP is a tool-server interface, not a lifecycle API for driving Cursor runs. [CLI parameters](https://cursor.com/docs/cli/reference/parameters) (checked 2026-09-24).
- **HTTP API:** Cursor’s Cloud Agents API is an HTTP surface for cloud agents; it is not the local, on-disk execution route specified for VIA. [Cloud Agents API](https://prod.cursor.com/docs/cloud-agent/api/endpoints) (checked 2026-09-24).

## 6. ACP support

- **Native or adapter:** Cursor CLI has **native ACP**: vendor docs say to launch `agent acp`; registry entry uses `cursor-agent acp`. The registry’s `cursor` item is not a third-party bridge. [Cursor ACP docs](https://cursor.com/docs/cli/acp) (checked 2026-09-24); [registry entry](https://raw.githubusercontent.com/agentclientprotocol/registry/main/cursor/agent.json) (version `2026.09.18`).
- **Who maintains the registry entry:** The entry lists authors as “Cursor,” proprietary license, and no source repository. The ACP registry repo is `agentclientprotocol/registry`; its README describes hourly automated version updates, and the entry’s Git history shows registry-maintainer commits. So Cursor owns the agent/version metadata, while the ACP registry maintainers curate and update the registry record. [Cursor entry](https://raw.githubusercontent.com/agentclientprotocol/registry/main/cursor/agent.json) (checked 2026-09-24); [registry README](https://github.com/agentclientprotocol/registry) (checked 2026-09-24); [entry history](https://github.com/agentclientprotocol/registry/commits/main/cursor) (checked 2026-09-24).
- **Transport and flow:** `agent acp` uses stdio, JSON-RPC 2.0, newline-delimited messages. Vendor docs describe initialize, authenticate, `session/new` or `session/load`, `session/prompt`, `session/update`, permission handling, and optional `session/cancel`. [Cursor ACP docs](https://cursor.com/docs/cli/acp) (checked 2026-09-24).
- **Capabilities advertised in vendor docs:** Create and load/resume a conversation; prompt and receive streaming updates; cancel; permission round-trip; agent/plan/ask modes. Docs do not list `session/list`, close, usage reporting, or a dedicated steer operation. ACP’s generic protocol defines optional load/list/resume/close-related capabilities, but generic protocol support must not be assumed to mean Cursor implements them. [Cursor ACP docs](https://cursor.com/docs/cli/acp) (checked 2026-09-24); [ACP session setup](https://agentclientprotocol.com/protocol/v1/session-setup) (checked 2026-09-24); [ACP session list](https://agentclientprotocol.com/protocol/v1/session-list) (checked 2026-09-24).
- **Model, effort, modes, sandbox:** Cursor’s ACP docs describe modes and permission requests but do not document model/effort selection or a sandbox-setting exchange. **UNVERIFIED:** whether global CLI options can configure model/sandbox before launching ACP. [Cursor ACP docs](https://cursor.com/docs/cli/acp) (checked 2026-09-24).
- **Auth:** ACP advertises `cursor_login`; Cursor says existing CLI login, `--api-key`/`CURSOR_API_KEY`, or `--auth-token`/`CURSOR_AUTH_TOKEN` can pre-authenticate. [Cursor ACP docs](https://cursor.com/docs/cli/acp) (checked 2026-09-24).
- **Potential hangs/losses:** ACP clients must reply to permission requests, or execution can block. Team-level MCP servers are not supported in ACP mode. Vendor docs do not promise token/cost reporting through ACP. [Cursor ACP docs](https://cursor.com/docs/cli/acp) (checked 2026-09-24).
- **Known bugs/issues:** **UNVERIFIED.** I found no Cursor-owned public issue tracker or release note documenting a specific current ACP spawn/resume/cancel/steer defect. Absence of a documented issue is not evidence that the capability works in all CLI versions.

## 8. Automation pitfalls

- **Terms ambiguity:** Headless docs promote scripts/CI, while the current AUP lists automated/script access as unacceptable. Treat this as a release-blocking terms question for VIA until Cursor clarifies. [Headless docs](https://cursor.com/docs/cli/headless); [AUP](https://prod.cursor.com/en-US/acceptable-use-policy) (last updated August 11, 2026).
- **Output drift:** Current docs say default `text`; an older official reference says default `stream-json`. Always set `--output-format` explicitly and parse terminal result events rather than intermediate assistant chunks. [Current output docs](https://cursor.com/docs/cli/reference/output-format); [older docs](https://docs.cursor.com/en/cli/reference/output-format).
- **Partial failures:** JSON failure may produce no valid JSON object; stream-json may end without a terminal result. Capture stderr and process exit status separately. [Output-format docs](https://cursor.com/docs/cli/reference/output-format).
- **Hangs:** ACP can wait indefinitely for user permission or Cursor’s blocking `cursor/ask_question` / `cursor/create_plan` extension replies. Client must answer or reject them and enforce its own timeout. [ACP docs](https://cursor.com/docs/cli/acp).
- **Trust and permissions:** `--trust` avoids workspace trust prompting in headless mode. `--force` changes command approval behavior; sandboxing is separately configurable. Do not conflate trust, command permission, and sandbox policy. [CLI parameters](https://cursor.com/docs/cli/reference/parameters).
- **Missing data:** CLI JSON does not document token/cost fields; SDK is needed for those. SDK cost may be absent until settlement. [CLI output docs](https://cursor.com/docs/cli/reference/output-format); [Python SDK](https://cursor.com/docs/sdk/python).
- **Session uncertainty:** Invalid-ID behavior, storage path, exact shutdown semantics, and CLI fork semantics are not documented in the sources reviewed; contract-test before depending on them. [CLI parameters](https://cursor.com/docs/cli/reference/parameters).

## 9. Recommendation

**Technically, use Cursor’s official SDK for VIA’s local adapter.** It offers documented local spawn/resume, run streaming/status/cancel, final text, token counts, and billed-cost lookup, which better matches VIA’s envelope than the CLI. Keep `steer` unsupported and expose it by name as unavailable. Use the CLI only as a simpler one-shot fallback when the SDK cannot be installed.

**Terms gate:** Do not represent personal-subscription automation as permitted until Cursor resolves the conflict between the headless automation docs and the AUP. The SDK is technically the strongest route, but its existence does not resolve that policy conflict. [Python SDK](https://cursor.com/docs/sdk/python); [Headless CLI docs](https://cursor.com/docs/cli/headless); [AUP](https://prod.cursor.com/en-US/acceptable-use-policy) (checked 2026-09-24).
