## Google’s Gemini CLI → Antigravity transition

**Confirmed:** Google announced a transition of its terminal experience from Gemini CLI to Antigravity CLI on **2026-05-19**, then documented that consumer Gemini Code Assist access—including free, Google AI Pro, and Ultra—stopped serving Gemini CLI requests on **2026-06-18**. Google said enterprise Code Assist and paid API access remain supported, and said it would keep Gemini CLI updated for those users. [Google Developers Blog](https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/), [official deprecation page](https://developers.google.com/gemini-code-assist/docs/deprecations/code-assist-individuals)

**So Google did de-prioritize Gemini CLI for consumers, but did not announce that the open-source CLI itself was discontinued.** Its current release history and changelog show active releases through September 2026. The live repository authentication documentation still mentions consumer Google login, contradicting the deprecation page; I found no official reversal. Treat consumer subscription login as **unavailable per the specific deprecation notice**, and the contradictory repository text as stale or unresolved. [Gemini CLI changelog](https://github.com/google-gemini/gemini-cli/blob/main/docs/changelogs/index.md), [repository auth docs](https://github.com/google-gemini/gemini-cli/blob/main/docs/get-started/authentication.mdx)

Keep these products distinct:

- **Antigravity IDE/Desktop** is Google’s graphical product; **Antigravity CLI** is a separate terminal program whose executable is `agy`. Google’s repo describes them as separate interfaces sharing an agent engine. [Repo README](https://github.com/google-antigravity/antigravity-cli)
- **`agy-acp-server` is not the `agy` CLI.** The ACP registry distributes a separate Google binary; its platform launch names are `agy_acp_server.par` on macOS/Linux and `agy_acp_server.exe` on Windows. The registry’s ACP version is 1.2.1 even though the CLI is now 1.2.10. [Registry manifest](https://github.com/agentclientprotocol/registry/blob/main/antigravity-acp/agent.json), [CLI releases](https://github.com/google-antigravity/antigravity-cli/releases)
- **Herdr’s `agy` kind means the `agy` CLI executable**, not the ACP server. Herdr says `--kind` selects a supported agent’s canonical executable; its agent documentation lists `agy`. [Herdr agent automation docs](https://herdr.dev/docs/agent-automation/)

## Antigravity CLI

**Identity, models, and access.** Google’s current Antigravity CLI is installed from Google’s platform installer and runs as `agy`; its latest release is **1.2.10, 2026-09-24**. The GitHub repo is public, but it contains docs, examples, and changelog rather than CLI source; the ACP registry calls the distributed server license proprietary. [Install docs](https://antigravity.google/docs/cli/install/), [repo](https://github.com/google-antigravity/antigravity-cli), [releases](https://github.com/google-antigravity/antigravity-cli/releases), [registry](https://github.com/agentclientprotocol/registry/blob/main/antigravity-acp/agent.json)

Classify it as **tier 1**, not a general model aggregator: Google’s product model list includes Gemini, Claude, and GPT-OSS choices within Antigravity plans, but the documented CLI API-key route is a Gemini API key. I found no official support for arbitrary provider credentials such as a user’s Anthropic API key or ChatGPT subscription. [Models](https://www.antigravity.google/docs/models/), [CLI auth](https://antigravity.google/docs/cli/install/)

**Headless and lifecycle.** `agy -p PROMPT` supports `text`, `json`, and `stream-json`. JSON reports `conversation_id`, status, response, duration, turns, and token counts; it does not document a cost field. `--model`, `--effort`, `--continue`, `--conversation ID`, `--sandbox`, and `--dangerously-skip-permissions` are documented. Stream-JSON stdin supports multiple turns and programmatic prompts; control-request/response events are unsupported, so **mid-turn steering semantics are not confirmed**. Successful runs exit 0; documented failures exit non-zero. [Headless mode](https://antigravity.google/docs/cli/headless/)

Headless mode needs cached credentials; an unauthenticated non-TTY run exits with an authentication error rather than opening a browser. In headless mode, tools needing unavailable approval are soft-denied unless permitted in settings; broad permission bypass is available but not needed for VIA’s basic read-only/result contract. [Headless mode](https://antigravity.google/docs/cli/headless/)

**Other surfaces and ACP.** Google publishes a Python SDK, `google-antigravity`, with a stateful agent/session API, tool hooks, MCP client support, and Gemini API-key or Vertex authentication. It is a distinct programmatic surface from wrapping the CLI. I found no official claim that `agy` itself can run as an MCP server. [SDK docs](https://www.antigravity.google/docs/sdk/overview), [SDK repo](https://github.com/google-antigravity/antigravity-sdk-python)

The ACP route is Google’s separate registry-distributed server, not an `agy --acp` flag. The registry lists its binary as version 1.2.1 and labels it proprietary. Its precise protocol maturity and advertised capabilities are **UNVERIFIED** from the manifest. A current upstream issue reports that ACP does not expose token usage; another open issue reports missing live file diffs. [Registry entry](https://github.com/agentclientprotocol/registry/blob/main/antigravity-acp/agent.json), [usage issue #1045](https://github.com/google-antigravity/antigravity-cli/issues/1045), [diff issue #1021](https://github.com/google-antigravity/antigravity-cli/issues/1021)

**VIA fit and access constraint.** Google’s Antigravity terms explicitly say using third-party software or tools to access Antigravity through OAuth (example: OpenClaw with Antigravity OAuth) breaches the agreement and may lead to account suspension. Thus, running VIA around `agy` with a user’s Antigravity subscription has a direct terms conflict. The CLI also documents a Gemini API-key mode; whether Google considers VIA’s use of that mode covered by the Antigravity OAuth restriction is **UNVERIFIED**. [Terms](https://antigravity.google/terms), [CLI API-key setup](https://antigravity.google/docs/cli/install/)

## Gemini CLI

**Identity, models, and access.** Gemini CLI is Google’s open-source, Apache-2.0 TypeScript CLI, installed as `@google/gemini-cli` and run with `gemini`. Stable **0.61.0** was released **2026-09-23**; the repo also lists newer nightly builds. It is actively maintained: recent weekly changelog entries and 107k GitHub stars. [Repo](https://github.com/google-gemini/gemini-cli), [changelog](https://github.com/google-gemini/gemini-cli/blob/main/docs/changelogs/index.md), [releases](https://github.com/google-gemini/gemini-cli/releases)

It is **tier 1**: Google’s docs describe Gemini API, Vertex AI, and Google/Code Assist authentication; they do not document upstream support for outside model providers. The official consumer-account deprecation page says consumer Google login stopped serving Gemini CLI on June 18, while enterprise Code Assist and paid API access remain. The repo’s auth guide still lists personal accounts and Pro/Ultra, so the precise live behavior is **UNVERIFIED** pending a current runtime check. [Authentication guide](https://github.com/google-gemini/gemini-cli/blob/main/docs/get-started/authentication.mdx), [deprecation page](https://developers.google.com/gemini-code-assist/docs/deprecations/code-assist-individuals)

**Headless and lifecycle.** `gemini -p PROMPT` provides text, JSON, or stream-JSON. The headless docs describe a JSON response with usage stats, and stream events include session metadata, model, messages, tool calls/results, and final aggregated statistics. `--model`, `--sandbox`, `--approval-mode`, and `--resume` are documented. The headless guide documents exit codes 0, 1, 42, and 53. Headless mode requires existing cached auth or environment-configured API-key/Vertex auth; a fresh browser login is not a headless bootstrap. [Headless guide](https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/headless.md), [CLI reference](https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/cli-reference.md), [auth guide](https://github.com/google-gemini/gemini-cli/blob/main/docs/get-started/authentication.mdx)

**Other surfaces and ACP.** Gemini CLI supports MCP servers as tools/extensions and has a documented A2A server package; no official MCP-server mode for exposing Gemini CLI as an MCP agent was confirmed. Its native ACP mode is `gemini --acp` over JSON-RPC on stdio, documented with `initialize`, `newSession`, `loadSession`, `prompt`, and `cancel`. Registry version is **0.61.0**, launching `npx @google/gemini-cli@0.61.0 --acp`. The docs do not state a maturity label or confirm usage propagation. [ACP docs](https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/acp-mode.md), [ACP registry](https://github.com/agentclientprotocol/registry/blob/main/gemini/agent.json), [MCP docs](https://github.com/google-gemini/gemini-cli/blob/main/docs/tools/mcp-server.md)

Known ACP reports include an open issue from August 2026 where `loadSession` erases the session it tries to load, and a March 2026 report of non-JSON stdout breaking the protocol stream, closed as not planned. There are also reports of ACP hanging when the agent encounters an approval or other input request. These are issue reports, not proof every current version is affected. [Load-session issue](https://github.com/google-gemini/gemini-cli/issues/28775), [stdout issue](https://github.com/google-gemini/gemini-cli/issues/22647), [approval/hang discussion](https://github.com/google-gemini/gemini-cli/discussions/15885)

**VIA fit and access constraint.** Google’s Gemini CLI terms say using third-party tools to directly access services such as Gemini Code Assist through Gemini CLI OAuth violates its terms. For VIA, that rules out presenting consumer or enterprise OAuth as an approved “use your subscription” route. API-key and Vertex paths are documented options, but those are API/cloud credentials rather than subscription login. [Gemini CLI terms and privacy](https://github.com/google-gemini/gemini-cli/blob/main/docs/resources/tos-privacy.md)
