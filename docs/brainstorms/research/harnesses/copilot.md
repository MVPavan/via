# GitHub Copilot CLI research

**Checked 2026-09-24.** Copilot CLI is not installed here (`copilot` was not found on `PATH`), so there is no local version or help output to report. This is live-source research, not a runtime probe. I found no Copilot profile in VIA’s `workflow_interpreter/profiles/`; the local handoff scopes v0 to Claude, Codex, and OpenCode. ## 1. Identity

GitHub Copilot CLI is GitHub’s terminal coding agent, distributed as `@github/copilot`; install options include npm, Homebrew, WinGet, and install scripts. Its repository publishes source, but the CLI is **not open source**: its license permits installing and running it, restricts modification, and allows redistribution only under conditions. The Copilot SDK is a separate project under MIT license. ([install docs](https://docs.github.com/en/copilot/how-tos/copilot-cli/set-up-copilot-cli/install-copilot-cli), [CLI license](https://github.com/github/copilot-cli/blob/main/LICENSE.md), [SDK repo](https://github.com/github/copilot-sdk), checked 2026-09-24)

**Version is inconsistent across upstream sources:** the GitHub Releases page showed stable **1.0.86**, released 2026-09-17; the ACP Registry’s live snapshot listed **1.0.88** for GitHub Copilot CLI. I can’t confirm from those sources whether 1.0.88 was a stable CLI release or registry version drift. Releases are frequent: the CLI’s release history shows many patch releases and prereleases, sometimes close together. ([CLI releases](https://github.com/github/copilot-cli/releases), [ACP Registry entry](https://cdn.agentclientprotocol.com/registry/v1/latest/registry.json), checked 2026-09-24)

The SDK Releases page showed stable **1.0.14** and prerelease **1.0.15-preview.2** dated 2026-09-23. Its README calls the SDK generally available. ([SDK releases](https://github.com/github/copilot-sdk/releases), [SDK README](https://github.com/github/copilot-sdk), checked 2026-09-24)

## 2. Auth and billing

With GitHub-hosted models, CLI and SDK use a Copilot subscription and GitHub authentication. OAuth via `copilot login` is the documented interactive path; automation can use `COPILOT_GITHUB_TOKEN`, `GH_TOKEN`, or `GITHUB_TOKEN`. A fine-grained PAT must be user-owned and have the Copilot Requests account permission; classic PATs are unsupported. BYOK can run without GitHub login, using a supported provider API key. ([auth docs](https://docs.github.com/en/copilot/how-tos/copilot-cli/set-up-copilot-cli/authenticate-copilot-cli), checked 2026-09-24)

**Programmatic use on personal subscriptions is explicitly documented.** GitHub says Copilot CLI can run in scripts and CI, documents `copilot -p`, and states that CLI is available on Copilot plans; prompts consume AI Credits according to tokens and model. In the Actions case, GitHub documents that a PAT uses its owner’s Copilot seat entitlements. I found no vendor statement prohibiting headless use on a personal subscription. ([programmatic CLI docs](https://docs.github.com/en/copilot/how-tos/copilot-cli/automate-copilot-cli/run-cli-programmatically), [plans](https://docs.github.com/en/copilot/get-started/plans), [Actions billing](https://docs.github.com/en/copilot/concepts/agents/copilot-cli/copilot-cli-in-github-actions), checked 2026-09-24)

## 3. Headless CLI contract

- **Command:** `copilot -p PROMPT`; piping a prompt to `copilot` is also documented. If `-p` is present, piped input is ignored. `-s` emits only response text, omitting usage statistics; do not use it if parsing the session metadata or usage from stdout. ([programmatic docs](https://docs.github.com/en/copilot/how-tos/copilot-cli/automate-copilot-cli/run-cli-programmatically), [CLI reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference), checked 2026-09-24)
- **Output:** `text` is default; `--output-format=json` emits JSONL, one JSON object per line. GitHub documents the format but not a complete, versioned event schema. A user report against CLI 1.0.54 observed `assistant.message` with `data.content` and a terminal `result` event, and reported JSONL as a workaround when plain prompt output was missing. Treat exact event payloads as **UNVERIFIED across versions**; parse defensively and retain raw stdout/stderr. ([CLI reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference), [1.0.54 output issue](https://github.com/github/copilot-cli/issues/3544), checked 2026-09-24)
- **Final text/session/usage/errors:** JSONL is the machine-readable path; `-p`’s exit summary includes a `--resume=SESSION-ID` hint. Normal non-silent output includes usage statistics. Sessions also persist an `events.jsonl` log, workspace artifacts, and metadata under `~/.copilot/session-state/{session-id}/`. I found no stable CLI documentation mapping every event field to final text, session ID, tokens, cost, and errors. The CLI reference documents telemetry names for per-turn token counts and AI-unit consumption; its `cost` telemetry field is a model multiplier, **not monetary cost**. ([CLI reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference), [configuration directory](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-config-dir-reference), checked 2026-09-24)
- **Exit codes:** **UNVERIFIED.** Docs describe completion and JSONL output but don’t establish a complete exit-code contract distinguishing model failure, tool failure, cancellation, or success. Capture the actual process exit code, but don’t infer full task success from it alone. ([programmatic docs](https://docs.github.com/en/copilot/how-tos/copilot-cli/automate-copilot-cli/run-cli-programmatically), checked 2026-09-24)
- **Model/effort/role:** `--model`, `--effort` / `--reasoning-effort`, `--mode`, and `--agent` are available. Effort values documented are `low`, `medium`, `high`, `xhigh`, and `max`; model availability depends on account and policy. `--agent` selects a custom agent profile; custom instructions can load from `AGENTS.md` and related files. There is no documented generic CLI flag for arbitrary system-prompt replacement. ([CLI reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference), [model selection](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-programmatic-reference), checked 2026-09-24)
- **Permissions/sandbox:** `--allow-tool`, `--deny-tool`, `--allow-url`, `--available-tools`, `--allow-all-tools`, and `--allow-all` are documented. `--allow-all` grants tools, paths, and URLs; it is broad authority. `--sandbox` and `--no-sandbox` are documented as experimental; sandbox policy may be managed by enterprise settings. ([programmatic reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-programmatic-reference), [CLI reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference), checked 2026-09-24)
- **Working directory/extra directories:** `-C DIRECTORY` changes the working directory before other work; `--add-dir=PATH` grants file access to extra directories and treats their agents/skills as trusted configuration. `--worktree` can create or reuse an isolated Git worktree. ([CLI reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference), checked 2026-09-24)
- **First-run prompts/stdin:** Headless environments may select device-code login, which needs prior authentication if VIA cannot interact with the user. The CLI may request approval for tools unless appropriate flags or permissions are provided. Piped prompt support exists, but piped text is ignored when `-p` is also supplied. Repository extensions/hooks are disabled by default in prompt mode unless the folder is already trusted or relevant opt-ins are set. ([auth docs](https://docs.github.com/en/copilot/how-tos/copilot-cli/set-up-copilot-cli/authenticate-copilot-cli), [allow/deny tools](https://docs.github.com/en/copilot/how-tos/copilot-cli/use-copilot-cli/allowing-tools), [CLI reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference), checked 2026-09-24)
- **Structured output/timeouts:** CLI `-p` has no documented JSON Schema response option. A total-task timeout flag was not found; `COPILOT_TASK_WAIT_TIMEOUT_SECONDS` bounds waiting for background agents or shell commands (default 600 seconds), not the whole prompt. `--max-ai-credits` is a soft response limit and must be at least 30 credits. ([CLI reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference), [credit limits](https://docs.github.com/en/copilot/how-tos/copilot-cli/use-copilot-cli/set-session-limit), checked 2026-09-24)

## 4. Session lifecycle in the CLI

`--resume=ID` resumes a prior session; `--continue` resumes the most recent session in the current directory, falling back to the globally most recent. Bare `--resume` uses a TTY picker. In non-TTY use, if a picker is needed and unavailable, the CLI documents an error instead of silently starting a new session. `--session-id ID` resumes an exact match; an unmatched valid UUID starts a new session. `/fork [NAME]` forks an interactive session. ([CLI reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference), checked 2026-09-24)

Session files live below `~/.copilot/session-state/`; `COPILOT_HOME` changes the state/config directory. The documented CLI has no local general-purpose `steer` command or stable machine control socket for a running `-p` process. It does support remote sessions when account features permit them; that is a separate remote route. ([config directory](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-config-dir-reference), [CLI reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference), checked 2026-09-24)

**Cancel:** process termination is available to the wrapper, but I found no documented signal-to-cancel guarantee for `-p`; exact signal behavior is **UNVERIFIED**. The SDK has an explicit `abort()` method, described below. ([SDK README](https://github.com/github/copilot-sdk/blob/main/nodejs/README.md), checked 2026-09-24)

## 5. Other programmatic surfaces

- **Copilot SDK:** first-party SDKs for Python, Node/TypeScript, Go, .NET, Java, and Rust. It starts or connects to the Copilot CLI runtime over JSON-RPC and exposes typed sessions, lifecycle, event streaming, permissions, custom tools, and session state. Python and Node SDKs bundle the runtime; other SDKs may need a CLI installed. ([SDK repo](https://github.com/github/copilot-sdk), [Node SDK README](https://github.com/github/copilot-sdk/blob/main/nodejs/README.md), checked 2026-09-24)
- **SDK lifecycle advantage:** `createSession`, `resumeSession`, `listSessions`, `send`, `sendAndWait`, `abort`, `disconnect`, and `getEvents` are documented. `send` offers `enqueue` or `immediate` delivery; `sendAndWait` supports a timeout. The Node SDK offers JSON Schema/Zod structured output, but labels it **preview** and requires a compatible runtime. ([Node SDK README](https://github.com/github/copilot-sdk/blob/main/nodejs/README.md), checked 2026-09-24)
- **Server/app-server:** the SDK manages the CLI server process or connects to one over stdio/TCP/URI. This is the underlying JSON-RPC server surface used by the SDK, not a separate public app-server contract I would recommend VIA implementing directly. ([SDK README](https://github.com/github/copilot-sdk/blob/main/nodejs/README.md), checked 2026-09-24)
- **MCP:** Copilot CLI can act as an MCP *client* with configured MCP servers/tools. I found no official evidence in the reviewed sources for a general Copilot CLI MCP-server mode that exposes its agent to VIA. ([CLI reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference), checked 2026-09-24)
- **HTTP:** ACP supports a `--port` TCP listener, but it is ACP over NDJSON/TCP, not an HTTP server. I found no general HTTP agent server surface in the reviewed first-party docs. ([ACP docs](https://docs.github.com/en/copilot/reference/copilot-cli-reference/acp-server), checked 2026-09-24)

## 6. ACP support

Copilot CLI implements ACP natively with `copilot --acp`; it is **not a third-party adapter**. ACP is in public preview. The GitHub-maintained CLI repo is source-published under its proprietary license. The ACP Registry listed `github-copilot-cli`, version 1.0.88, publisher GitHub, `@github/copilot@1.0.88`, launched with `--acp`; its snapshot does not enumerate capabilities. ([ACP docs](https://docs.github.com/en/copilot/reference/copilot-cli-reference/acp-server), [ACP Registry](https://cdn.agentclientprotocol.com/registry/v1/latest/registry.json), [CLI license](https://github.com/github/copilot-cli/blob/main/LICENSE.md), checked 2026-09-24)

**Launch:** `copilot --acp --stdio` (default transport) or `copilot --acp --port 3000` (TCP, loopback by default). Both use newline-delimited JSON. Stdio ties server lifetime to the parent process; TCP stays up until stopped. The ACP server authenticates using the user’s CLI auth, or BYOK provider config without GitHub login. ([ACP docs](https://docs.github.com/en/copilot/reference/copilot-cli-reference/acp-server), checked 2026-09-24)

**Capabilities and controls:**

- The official example demonstrates initialize → `session/new` → `session/prompt` and streamed `agent_message_chunk` notifications. ACP `session/new` carries working directory and MCP servers, but not tool filters or reasoning effort; those must be fixed at server launch. ([ACP docs](https://docs.github.com/en/copilot/reference/copilot-cli-reference/acp-server), checked 2026-09-24)
- A CLI repo issue report against 1.0.84-1 says initialize advertised `loadSession`, session close/list, image and embedded-context prompts; CLI changelog later says ACP added session close and token usage in prompt results plus `usage_update`. Treat exact current capability negotiation as **UNVERIFIED until VIA probes the installed version**. ([1.0.84-1 capability report](https://github.com/github/copilot-cli/issues/4743), [CLI changelog](https://github.com/github/copilot-cli/blob/main/changelog.md), checked 2026-09-24)
- ACP supports cancellation in the CLI’s implementation, but issue reports describe problematic behavior: one says a later `session/prompt` unconditionally aborts background subagents; another says cancellation can return `end_turn` rather than `cancelled`. These are user reports, not independently verified here. ([ACP prompt-abort report](https://github.com/github/copilot-cli/issues/4555), [cancel stopReason report](https://github.com/github/copilot-cli/issues/4561), checked 2026-09-24)
- **Steering:** there is no distinct mid-turn “inject input” feature confirmed in the reviewed ACP docs. Sending another prompt while work is active is not a safe equivalent, given the reported abort issue. Mark mid-turn steering **UNVERIFIED/unsupported for VIA until tested**. ([ACP docs](https://docs.github.com/en/copilot/reference/copilot-cli-reference/acp-server), [ACP prompt-abort report](https://github.com/github/copilot-cli/issues/4555), checked 2026-09-24)
- Model selection is possible through the ACP model config surface in some versions, but `auto` was reportedly rejected by `session/set_model` in CLI 1.0.32. For reliable configuration, launch a server pinned with `--effort` / `--reasoning-effort` and choose model at session creation only if the negotiated model capability permits it. Sandbox/tool filtering are server-launch configuration, shared by every session on that process; the client cannot choose them per-session. Usage is available in newer ACP prompt results and `usage_update` per the CLI changelog. ([ACP docs](https://docs.github.com/en/copilot/reference/copilot-cli-reference/acp-server), [1.0.32 model report](https://github.com/github/copilot-cli/issues/2843), [CLI changelog](https://github.com/github/copilot-cli/blob/main/changelog.md), checked 2026-09-24)
- **Lost vs CLI/SDK:** ACP is a session protocol and streams progress, but the preview’s effective behavior/capabilities vary by CLI version; server-level effort/tool settings reduce per-session isolation. The SDK provides a richer typed API, local event history and direct abort/steering APIs. ([ACP docs](https://docs.github.com/en/copilot/reference/copilot-cli-reference/acp-server), [SDK README](https://github.com/github/copilot-sdk/blob/main/nodejs/README.md), checked 2026-09-24)

## 8. Automation pitfalls

- **Output drift:** JSONL is documented, but the complete schema is not. A CLI issue documents a 1.0.54 case where normal stdout omitted final text; JSONL was the workaround. Pin versions and preserve logs. ([CLI ref](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference), [issue #3544](https://github.com/github/copilot-cli/issues/3544), checked 2026-09-24)
- **Hangs or hidden work:** CLI waits up to 600 seconds by default for pending background agents/shells. ACP issue reports describe `end_turn` arriving before background work and subsequent output, and a later prompt aborting background agents. ([CLI ref](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference), [ACP issue #4743](https://github.com/github/copilot-cli/issues/4743), [ACP issue #4555](https://github.com/github/copilot-cli/issues/4555), checked 2026-09-24)
- **Auth prompts and ambient config:** headless machines can require device-code login beforehand; token environment variables silently override stored OAuth credentials. `COPILOT_HOME` isolates config and sessions. ([auth docs](https://docs.github.com/en/copilot/how-tos/copilot-cli/set-up-copilot-cli/authenticate-copilot-cli), [CLI ref](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference), checked 2026-09-24)
- **Permissions:** `-p` can still need permission configuration for actions; `--allow-all` grants broad access. Start with least privilege and an explicit sandbox/profile. ([programmatic reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-programmatic-reference), checked 2026-09-24)
- **Rate limits/cost:** usage is AI Credits, model-dependent; `--max-ai-credits` is a soft cap, not a strict billing ceiling. ([credit limits](https://docs.github.com/en/copilot/how-tos/copilot-cli/use-copilot-cli/set-session-limit), checked 2026-09-24)
- **Version churn:** release history is frequent, ACP is preview, and registry/release versions disagreed during this research. Pin both SDK and runtime; SDK docs explicitly recommend doing so. ([CLI releases](https://github.com/github/copilot-cli/releases), [ACP Registry](https://cdn.agentclientprotocol.com/registry/v1/latest/registry.json), [SDK usage/billing guidance](https://docs.github.com/en/copilot/how-tos/copilot-sdk/features/usage-and-billing), checked 2026-09-24)

## 9. Recommendation

**Use the Copilot SDK for a VIA adapter that must honor the full session contract.** It is first-party, GA per its repository, has session IDs and event history, supports resume, immediate steering, abort, listing, and timeout-aware waits. That maps more closely to VIA’s verbs and envelope than parsing CLI output or relying on preview ACP behavior. Since VIA is Python-based, start with the Python SDK and pin both SDK and bundled/runtime version; keep structured output optional because the Node docs mark it preview, and verify the Python SDK’s exact schema API before depending on it. ([SDK repo](https://github.com/github/copilot-sdk), [Python SDK](https://github.com/github/copilot-sdk/tree/main/python), [Node SDK API](https://github.com/github/copilot-sdk/blob/main/nodejs/README.md), checked 2026-09-24)

If VIA adds Copilot only for the current one-shot v0 scope, `copilot -p --output-format=json` is a simpler subprocess route for **spawn/resume/result**; declare **steer unsupported** and **cancel partial** for that adapter. Don’t use ACP as the v0 control surface until VIA has version-pinned probes for cancellation, session close, prompt timing, model selection, and usage. ([VIA handoff](<../../../workstreams/handoff.md>), [CLI reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference), [ACP docs](https://docs.github.com/en/copilot/reference/copilot-cli-reference/acp-server), checked 2026-09-24)
