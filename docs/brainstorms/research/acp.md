# ACP and VIA: research report

**Checked 2026-09-24.** ACP’s latest stable schema release I found was **v1.23.0 (2026-09-18)**; its wire protocol version is **1**. Capability claims below are version-scoped where the source only documents a particular release. **UNVERIFIED** means I could not confirm the detail in the reviewed primary sources; it does not mean unsupported. ([ACP releases](https://github.com/agentclientprotocol/agent-client-protocol/releases), [ACP overview](https://agentclientprotocol.com/protocol/v1/overview))

## 1. ACP itself

ACP is designed to connect a **client** to an **agent**. The client initiates the connection, creates sessions, sends prompts, handles permission requests, and receives updates; the agent runs the model/tool loop. VIA would be the client and the harness or bridge process the agent. ACP describes agents as commonly running as client subprocesses, so **an editor is not required**. ([ACP overview](https://agentclientprotocol.com/protocol/v1/overview), [Copilot ACP server docs](https://docs.github.com/en/copilot/reference/copilot-cli-reference/acp-server))

The protocol uses JSON-RPC 2.0. Local ACP agents commonly exchange newline-delimited JSON-RPC over stdio; OpenCode and Gemini document that transport, and GitHub documents stdio plus an optional TCP mode for Copilot. ([ACP overview](https://agentclientprotocol.com/protocol/v1/overview), [OpenCode ACP docs](https://opencode.ai/v2/docs/cli/acp/), [Gemini ACP docs](https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/acp-mode.md), [Copilot ACP server docs](https://docs.github.com/en/copilot/reference/copilot-cli-reference/acp-server))

| Capability | ACP mechanism | What it means for VIA |
|---|---|---|
| Create session | `session/new`; agent returns a session ID. | Structured session creation, subject to the agent implementing it. ([Session setup](https://agentclientprotocol.com/protocol/v1/session-setup)) |
| Send a turn | `session/prompt`; the client receives `session/update` notifications while the request is running. | Structured input and progress. VIA still collects the updates into its result. ([Prompt turn](https://agentclientprotocol.com/protocol/v1/prompt-turn)) |
| Load or resume | Optional `session/load` replays history; optional `session/resume` restores state without replay. Agents advertise these capabilities. | VIA must check the actual agent’s handshake and persist its session ID. ([Session setup](https://agentclientprotocol.com/protocol/v1/session-setup)) |
| Cancel | `session/cancel` notification; the prompt should finish with stop reason `cancelled`. | A turn-level cancel contract, but actual interruption behavior depends on the agent. ([Prompt turn](https://agentclientprotocol.com/protocol/v1/prompt-turn)) |
| Permissions | Agent calls client method `session/request_permission`; the client returns an outcome. | VIA must implement a policy for approve, deny, or cancel. It cannot assume a human editor is present. ([ACP overview](https://agentclientprotocol.com/protocol/v1/overview), [Prompt turn](https://agentclientprotocol.com/protocol/v1/prompt-turn)) |
| Tool and file updates | `session/update` carries message chunks, tool-call updates, and other events. Tool-call content can include diffs. | Structured progress and edits when the agent emits them; not a guarantee that every native detail is preserved. ([ACP overview](https://agentclientprotocol.com/protocol/v1/overview), [Tool calls and diffs](https://agentclientprotocol.com/protocol/v1/tool-calls)) |
| Turn completion | The `session/prompt` response contains a `stopReason` such as `end_turn`, `max_tokens`, `max_turn_requests`, `refusal`, or `cancelled`. Final text arrives in message chunks. | VIA must concatenate/select final text and normalize stop reason; ACP’s response is not itself a complete VIA result envelope. ([Prompt turn](https://agentclientprotocol.com/protocol/v1/prompt-turn), [Schema](https://agentclientprotocol.com/protocol/v1/schema)) |
| Usage and cost | Stable `usage_update` reports context tokens used/size and **optional cumulative session cost**. | It does **not** guarantee per-turn input/output token counts or cost. Whether a given agent supplies usage is implementation-specific. ([Schema](https://agentclientprotocol.com/protocol/v1/schema)) |

The stable v1 surface is mature enough to have a released schema and interoperable implementations. It is also still evolving: the ACP release page lists **schema v2.0.0-alpha.5** as prerelease, and v1 releases continue to add or stabilize fields. ([ACP releases](https://github.com/agentclientprotocol/agent-client-protocol/releases))

## 3. VIA verb mapping

| VIA verb | ACP provides | VIA still needs |
|---|---|---|
| **spawn** | `session/new` plus `session/prompt` for the initial turn. | Launch/supervise the agent process; supply role instructions, model/effort, and sandbox configuration; create VIA run ID and durable record. ACP’s session ID is an agent conversation ID, not a process exit code. ([Session setup](https://agentclientprotocol.com/protocol/v1/session-setup)) |
| **resume** | Optional `session/load` or `session/resume`. | Capability detection, persistence of IDs and launch configuration, and refusal when an agent cannot restore a session. “Load” and “resume” have different replay semantics. ([Session setup](https://agentclientprotocol.com/protocol/v1/session-setup)) |
| **steer** | **No standard v1 mid-turn input method.** A new `session/prompt` is for a prompt turn; mid-turn steering appears in agent-specific extensions such as `_session/steering`. ([Prompt turn](https://agentclientprotocol.com/protocol/v1/prompt-turn), [ACP steering proposal](https://github.com/orgs/agentclientprotocol/discussions/1220)) | VIA must expose per-adapter steer capability and semantics, including whether input is injected, queued, or refused. Do not map ordinary `session/prompt` to “steer.” |
| **cancel** | `session/cancel` requests cancellation of the active prompt turn. ([Prompt turn](https://agentclientprotocol.com/protocol/v1/prompt-turn)) | Decide whether VIA cancel means turn cancellation, whole session close, or process termination; observe the result and enforce a timeout if the agent fails to stop. Session close is separately capability-gated. ([Session setup](https://agentclientprotocol.com/protocol/v1/session-setup)) |
| **status** | Streaming updates and optional session metadata/list capabilities. There is no universal status query that reliably reports process liveness and current turn state across agents. ([ACP overview](https://agentclientprotocol.com/protocol/v1/overview), [Session setup](https://agentclientprotocol.com/protocol/v1/session-setup)) | Maintain the run ledger and process state; normalize ACP notifications plus process exit into VIA status. |
| **result** | Message chunks and a required `stopReason`; optional session usage updates. ([Prompt turn](https://agentclientprotocol.com/protocol/v1/prompt-turn), [Schema](https://agentclientprotocol.com/protocol/v1/schema)) | Aggregate final text, map stop reason to VIA status, capture exit code/stderr/logs, and represent absent or cumulative-only usage without inventing per-turn values. |

**Steer answer:** not in ACP v1 core. It is possible where an agent exposes a negotiated or documented extension, but those extensions are not interoperable by virtue of being ACP.

## 4. Alternatives and competitors

| Option | Fit for VIA |
|---|---|
| **Native CLI adapters** | Closest to VIA’s existing design: preserves each harness’s own headless output, sandbox flags, and exit status. It keeps per-harness parsing and release drift. Anthropic documents print/JSON/stream-JSON and resume for Claude Code; Gemini and Cursor document comparable headless/session features. ([Claude CLI reference](https://docs.anthropic.com/en/docs/claude-code/cli-usage), [Gemini CLI reference](https://github.com/google-gemini/gemini-cli/blob/main/docs/reference/configuration.md), [Cursor CLI reference](https://docs.cursor.com/en/cli/reference/parameters)) |
| **Vendor SDKs / app servers** | Better when a vendor exposes a richer supported control surface. Anthropic’s Agent SDK documents sessions, resume/fork, streaming, approvals, and structured output. Codex App Server documents JSON-RPC threads/turns, resume, interrupt, model and sandbox parameters, and structured events. Both remain vendor-specific. ([Anthropic Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview), [Codex App Server](https://developers.openai.com/codex/app-server)) |
| **A2A** | Targets communication between independent agents over HTTP(S), with task IDs, task states, artifacts, and cancellation. It is useful for remote agent delegation, but it does not standardize local coding-CLI launch flags or harness session semantics. The reviewed official spec identifies v0.3.0 as latest. ([A2A specification](https://a2a-protocol.org/v0.3.0/specification/)) |
| **MCP** | Standardizes tools, resources, and prompts made available to model clients. It is not a general coding-agent session-control protocol. MCP’s Tasks extension may be relevant for long-running tool operations, but that still does not supply each harness’s model, sandbox, or session contract. ([MCP server overview](https://modelcontextprotocol.io/specification/draft/server/index), [MCP roadmap](https://blog.modelcontextprotocol.io/posts/mcp-roadmap/)) |

## 5. Risks

- **Churn and optionality:** ACP’s v1 schema is released, but the repository also publishes unstable additions and v2 alpha releases. Capability negotiation and version pinning are necessary. ([ACP releases](https://github.com/agentclientprotocol/agent-client-protocol/releases))
- **Adapter lag and implementation bugs:** ACP normalizes messages but cannot guarantee the wrapped harness honors load, cancel, or steering semantics. Reported examples include Gemini session-history restoration and Claude steering lifecycle gaps. ([Gemini report](https://github.com/google-gemini/gemini-cli/issues/27913), [Claude report](https://github.com/agentclientprotocol/claude-agent-acp/issues/934))
- **Feature loss:** ACP’s generic session setup is not a universal carrier for model, effort, sandbox, permission, or every CLI flag. Implementations may expose config options or extensions; Copilot specifically documents server-start options that cannot be changed per session. ([ACP schema](https://agentclientprotocol.com/protocol/v1/schema), [Copilot ACP docs](https://docs.github.com/en/copilot/reference/copilot-cli-reference/acp-server))
- **Result-shape limits:** ACP standardizes chunks and stop reasons, not VIA’s full envelope. Stable usage reports context occupancy and optional cumulative cost; per-turn token accounting is not guaranteed. ([ACP schema](https://agentclientprotocol.com/protocol/v1/schema))
- **Licensing:** The ACP registry is Apache-2.0, but says individual agents have their own licenses. Audit each adapter, SDK, and harness dependency before bundling or redistributing it. ([Registry license note](https://github.com/agentclientprotocol/registry))
- **Operational boundary:** The editor-free stdio model is suitable for headless clients, but VIA must own permissions, subprocess lifetime, logs, exit codes, and durable run records. ([ACP overview](https://agentclientprotocol.com/protocol/v1/overview), [Copilot ACP docs](https://docs.github.com/en/copilot/reference/copilot-cli-reference/acp-server))

## 6. Recommendation for VIA

**Use ACP for some adapters and native control for others.** Make ACP a reusable transport/normalization layer where a maintained implementation preserves the controls VIA needs; keep a native adapter or vendor SDK path when it exposes material capabilities ACP does not.

- **Good ACP candidates to evaluate first:** OpenCode’s native ACP and the ACP-maintained Codex bridge both document structured sessions, cancellation, and lifecycle support. Codex’s bridge is itself layered on the Codex App Server, which may be the stronger route if VIA needs Codex-specific settings or exact event fidelity. ([OpenCode ACP](https://opencode.ai/v2/docs/cli/acp/), [Codex ACP](https://github.com/agentclientprotocol/codex-acp), [Codex App Server](https://developers.openai.com/codex/app-server))
- **Claude:** The ACP bridge is official within the ACP project and uses Anthropic’s Agent SDK, but it is not simply the existing Claude Code CLI adapter. Compare output, permissions, and session behavior before treating them as interchangeable. ([Claude ACP bridge](https://github.com/agentclientprotocol/claude-agent-acp), [Anthropic Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview))
- **Do not make ACP universal yet:** Gemini restore behavior, Cursor’s official ACP status, and several agents’ current cancel/steer capabilities were not confirmed here; Copilot labels ACP preview and documents per-server configuration limits. Keep these behind adapter-specific capability declarations and version-pinned contract checks. ([Gemini report](https://github.com/google-gemini/gemini-cli/issues/27913), [Cursor docs](https://docs.cursor.com/en/cli/reference/parameters), [Copilot ACP docs](https://docs.github.com/en/copilot/reference/copilot-cli-reference/acp-server))
- **Retain VIA’s own contract:** ACP can reduce output-protocol work, but VIA still needs its run ID/ledger, process exit and log capture, status/result envelope, and honest verb capability declarations. In particular, offer `steer` only when the chosen backend advertises a tested steering extension; ACP v1 alone does not provide it. ([ACP schema](https://agentclientprotocol.com/protocol/v1/schema), [ACP steering proposal](https://github.com/orgs/agentclientprotocol/discussions/1220))
