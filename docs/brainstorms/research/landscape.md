# VIA research report: coding-agent communication and delegation

**Snapshot:** 24 September 2026. Sources below are official docs, protocol specifications, or project repositories, checked on that date unless a page names a version. A repository’s README documents what its maintainers claim; it does not establish that the behavior works reliably in production. **UNVERIFIED** marks behavior I could not confirm from primary sources.

## 1. Taxonomy of mechanisms

| Mechanism | How results return | Resume, steering, cancel | Isolation and fit for VIA |
|---|---|---|---|
| **In-harness subagents** — Claude Code, Codex, OpenCode | A parent agent delegates through native tools and receives child output in its own run. OpenAI’s Agents API documents child contexts and orchestration actions including spawn, message, follow-up, wait, and interrupt. [OpenAI Agents API multi-agent docs](https://developers.openai.com/api/docs/guides/agents-api/multi-agent), checked 2026-09-24. | Lifecycle is harness-defined; these tools are not a cross-harness contract. The Agents API distinguishes interrupting a child from deleting its context. Claude Code’s CLI documents session resume, while its native child lifecycle is a separate in-harness mechanism. [Claude Code CLI reference](https://docs.anthropic.com/en/docs/claude-code/cli-usage), checked 2026-09-24. | Useful when the parent and child share a runtime and its context model. The result and controls remain coupled to that runtime; VIA would need an adapter to expose them uniformly. |
| **Headless CLI invocation** — `claude -p`, `codex exec`, Gemini CLI, `opencode run` | The caller starts a process and reads stdout/stderr and exit status. Formats vary: Claude supports text, JSON, and stream JSON; Gemini documents JSON/JSONL events, session metadata, token statistics, errors, and exit codes. [Claude Code CLI reference](https://docs.anthropic.com/en/docs/claude-code/cli-usage); [Gemini CLI headless reference](https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/headless.md), checked 2026-09-24. | Claude documents session resume by ID. Codex’s local comparison describes `codex exec --json` plus a resume command; current flags and semantics should be checked against the installed CLI before implementation. [VIA handoff](<../../workstreams/handoff.md>); [Herdr/Orca comparison](<https://github.com/MVPavan/coding-ritual/blob/09cee1bac75cf2ec6c23839ba3f1c069be80b379/docs/research/codebases/comparison-herdr-orca.md>). | One process per turn maps naturally to `spawn` and a result envelope. The caller can terminate a process, but durable cancellation, follow-up turns, and safe resume require vendor-specific support. Headless mode can still encounter permissions, trust prompts, or output drift. |
| **Vendor SDKs and app-server APIs** — Claude Agent SDK, Codex SDK/app-server, OpenCode SDK/API | Typed events, messages, or session/turn objects can carry richer results than terminal text. Claude Agent SDK offers a programmatic Claude Code runtime; OpenAI distinguishes its managed Agents API from the in-process Agents SDK; Codex CLI can also be exposed through its MCP server. [Claude Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview); [OpenAI agent runtime comparison](https://developers.openai.com/api/docs/guides/agents); [Codex CLI MCP cookbook](https://developers.openai.com/cookbook/examples/codex/codex_mcp_agents_sdk/building_consistent_workflows_codex_cli_agents_sdk), checked 2026-09-24. | Often richer than one-shot CLI calls, but the exact resume, interrupt, and mid-turn input semantics differ. The API/session/thread identity is vendor-specific. | Better source of structured lifecycle facts when supported; higher adapter cost and runtime coupling. SDK invocation can use a different control path, auth, or process lifetime than the CLI, so VIA must choose deliberately per adapter. |
| **MCP delegation** — agent exposed as a tool or MCP server | MCP tools return content and may return `structuredContent` validated against an `outputSchema`. The protocol has no implicit session state: stateful services need explicit handles in tool inputs/outputs. [MCP tools specification](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2026-07-28/server/tools.mdx), checked 2026-09-24. Codex’s cookbook demonstrates running Codex as an MCP server; Zen/PAL exposes model collaboration and CLI bridging through MCP tools. [Codex MCP cookbook](https://developers.openai.com/cookbook/examples/codex/codex_mcp_agents_sdk/building_consistent_workflows_codex_cli_agents_sdk); [PAL MCP repository](https://github.com/BeehiveInnovations/pal-mcp-server). | MCP itself does not define agent `resume`, `steer`, `cancel`, or `status`; a server must provide those tools and retain its own run/session IDs. Claude Code as a general-purpose MCP server: **UNVERIFIED** in the official sources checked. | A useful transport and tool interface, not a lifecycle contract by itself. A VIA MCP adapter could expose VIA’s verbs to hosts; VIA can also call other MCP servers, but that is not equivalent to running their underlying agent harnesses. |
| **Agent Client Protocol (ACP)** | JSON-RPC client/agent sessions; `session/prompt` returns a stop reason while `session/update` sends progress. Sessions can be created with `session/new`; `session/load` is optional and capability-gated. [ACP v1 overview](https://agentclientprotocol.com/protocol/v1/overview), checked 2026-09-24. | `session/cancel` is a defined notification; loading an existing session requires the agent to advertise `loadSession`. | Designed for editor/client ↔ coding-agent communication, with capability negotiation and permission requests. It is not itself a role-to-agent scheduler or uniform run record. Coverage of the target harnesses and cross-version contract-test behavior: **UNVERIFIED here**; a separate run is researching ACP in depth. |
| **Agent2Agent (A2A)** | Remote agent tasks, messages, artifacts, and status; supports synchronous and streaming/asynchronous task updates, task lookup/listing, and push notifications. [A2A specification](https://a2a-protocol.org/latest/specification/), checked 2026-09-24. | `CancelTask` exists; multi-turn/context IDs and task IDs are defined. Steering is represented through messages and task semantics, not a universal coding-agent continuation behavior. | Built for agent-to-agent service interoperability and discovery. It is a plausible remote adapter target, but does not itself define local process isolation, CLI version pinning, or a VIA-shaped result envelope. Separate A2A research is in progress. |
| **Terminal multiplexers and tmux orchestrators** | Usually screen text, pane state, or a custom status board; a pane’s text is not proof of a completed turn or structured result. | Can send keystrokes or terminate panes; resume is often “reattach to the terminal,” not resume a vendor session by ID. | Good visibility and human control. PTY-based interaction is vulnerable to trust/permission dialogs, prompt timing, and output parsing. Claude Squad documents separate tmux sessions and Git worktrees for agents. [Claude Squad repository](https://github.com/smtg-ai/claude-squad), checked 2026-09-24. |
| **Shared files, worktrees, issues, and Git as blackboards** | Agents exchange plans and results by writing files, commits, diffs, or issue updates; the orchestrator must inspect and interpret them. | A handoff file or issue can preserve context between runs, but does not guarantee harness-session resume. Steering happens via another file/comment or a new prompt. Cancellation is external to the blackboard. | Worktrees isolate file changes; shared branches and common workspaces do not. This is durable and portable but gives weak run identity, status, usage, and failure semantics without an additional ledger. |
| **Message buses and mailboxes** | Explicit messages with sender/recipient IDs and possibly durable queues or receipts. Orca’s prior inspection found persistent journal/mailbox patterns; Traycer’s open protocol describes inbox delivery/acknowledgement. Details and limitations are in the [local comparison](<https://github.com/MVPavan/coding-ritual/blob/09cee1bac75cf2ec6c23839ba3f1c069be80b379/docs/research/codebases/comparison-herdr-orca.md>). | A mailbox can support follow-up without recreating a session; whether the agent can be steered while running is implementation-specific. Cancel remains a separate control operation. | Stronger than a shared file for asynchronous coordination, but creates a second state system unless run identity and completion reconcile with the agent runtime. |
| **Cloud coding-agent APIs** — Jules, Copilot cloud agent, OpenAI Agents API, Devin | Return service-managed session/task state and artifacts such as branches, diffs, or PRs. GitHub documents an ephemeral Actions-powered environment and follow-up through the same conversation; Jules documents VM-based execution with plan approval. [Copilot cloud agent docs](https://docs.github.com/en/copilot/concepts/agents/cloud-agent/about-cloud-agent); [Jules getting started](https://jules.google/docs); [OpenAI Agents API](https://developers.openai.com/api/docs/guides/agents-api/overview), checked 2026-09-24. | Follow-up and cancellation are provider APIs/UI-specific. The OpenAI Agents API manages saved sessions, recovery, and orchestration; GitHub documents continued iteration; Jules exposes REST API and CLI navigation, but a shared cross-provider verb contract is absent from these docs. | Providers own the runtime and environment, so users get less control over local process details and harness choice. Devin’s API lifecycle details: **UNVERIFIED** in this pass. |

## 3. Recurring patterns and evidence

- **Worktree-per-agent** recurs in Claude Squad, Uzi, and Vibe Kanban. It isolates filesystem changes and makes diff review/selection practical; it does not isolate credentials, processes, or agent state by itself. [Claude Squad](https://github.com/smtg-ai/claude-squad); [Uzi](https://github.com/devflowinc/uzi); [Vibe Kanban](https://www.vibekanban.com/), checked 2026-09-24.
- **Planner → implementer → reviewer** appears in Conductor’s workflow examples and Zen/PAL’s planner, code-review, and consensus tools. It is a common product pattern; the sources do not establish that the split itself improves outcomes across coding tasks. [Microsoft Conductor](https://github.com/microsoft/conductor); [PAL MCP](https://github.com/BeehiveInnovations/pal-mcp-server).
- **Cross-model review and consensus** is explicitly offered by Zen/PAL and MCO. It gives a caller multiple perspectives, but “consensus” does not prove correctness; require evidence, independent checks, and a clear decision owner. [PAL MCP](https://github.com/BeehiveInnovations/pal-mcp-server); [MCO](https://github.com/mco-org/mco).
- **Durable handoff artifacts**—plans, issues, PRs, or files—are the broadest compatibility layer. Cloud agents and Kanban tools use branch/PR or task artifacts, while MCO exposes machine-readable outputs. These artifacts help recover work after a process ends, but are not substitutes for vendor session IDs, exit status, or usage metadata. [Copilot cloud agent](https://docs.github.com/en/copilot/concepts/agents/cloud-agent/about-cloud-agent); [Jules](https://jules.google/docs); [MCO](https://github.com/mco-org/mco).
- **Evidence of “working well”:** public docs demonstrate concrete capabilities and examples, not comparative outcome studies. I found evidence that tools implement these patterns, but not primary evidence that any one pattern reliably raises coding quality across harnesses. Treat efficacy as **UNVERIFIED**.

## 4. Is VIA’s niche occupied?

**Partly, but not completely in the sources reviewed.** MCO is the nearest local CLI-oriented comparison: it documents multi-provider adapters, polling, cancellation, output artifacts, exit codes, and error contracts. Microsoft Conductor documents repeatable, structured multi-provider workflows. Open Dynamic Workflow describes a similar CLI-workflow surface. None of the checked sources establishes the full combination VIA proposes: one contract-tested interface for role + prompt across harnesses, with durable run identity and a structured envelope, and explicit per-adapter `spawn`, `resume`, `steer`, `cancel`, `status`, and `result` capability semantics.

The closest **lifecycle** fit depends on scope:

- For local coding CLIs, **MCO** is the closest documented fit to multi-provider run/poll/cancel plus machine-readable results; durable resume and steer remain unverified. [MCO](https://github.com/mco-org/mco).
- For deterministic orchestration graphs and structured data flow, **Microsoft Conductor** is the closest documented workflow fit; it is not presented as a universal native-session control API. [Microsoft Conductor](https://github.com/microsoft/conductor).
- For a managed Codex harness, **OpenAI Agents API** already provides saved sessions, orchestration, recovery, multi-agent actions, and managed environments—but is OpenAI-specific. [Agents API overview](https://developers.openai.com/api/docs/guides/agents-api/overview); [multi-agent docs](https://developers.openai.com/api/docs/guides/agents-api/multi-agent).
- ACP and A2A may reduce protocol-level adapter work where target harnesses implement them, but neither protocol alone supplies VIA’s local process wrapper, result grading, worktree pins, role catalog, or universal semantics. [ACP v1 overview](https://agentclientprotocol.com/protocol/v1/overview); [A2A specification](https://a2a-protocol.org/latest/specification/).

**Assessment:** VIA’s niche is not “run several agents” or “make a workflow.” It is a narrow compatibility/control layer that keeps lifecycle and result claims honest across CLI and protocol adapters. The differentiator must be verified conformance and explicit unsupported-operation behavior; a common command vocabulary without those would only hide incompatible semantics.

## 5. Lessons and borrowable designs for VIA

1. **Separate the VIA run ID from the vendor session/thread ID.** Store both. Treat the vendor ID as opaque, scoped to an adapter and its version. Resume must fail loudly if the native session cannot be resumed; silently starting a new session risks losing the requested continuity. The local T3 Code comparison notes this exact Codex-resume failure mode. [Local comparison](<https://github.com/MVPavan/coding-ritual/blob/09cee1bac75cf2ec6c23839ba3f1c069be80b379/docs/research/codebases/comparison-herdr-orca.md>).
2. **Define a result envelope around observable facts:** adapter and version, run ID, vendor session ID, requested and resolved role/model/effort, terminal state, exit code, final text, usage/cost when available, timestamps, log/artifact paths, and input/output workspace pins. Keep “agent says done” separate from process/turn completion and from independent artifact grading. Gemini’s headless schema shows the value of session ID, usage stats, errors, and exit codes in machine-readable output. [Gemini CLI headless reference](https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/headless.md).
3. **Make capabilities explicit per adapter.** `resume`, `steer`, and `cancel` should be declared as supported with documented semantics, unsupported, or best-effort. ACP’s capability negotiation is a useful pattern; MCP’s lack of implicit session state is a reminder to require explicit run IDs. [ACP overview](https://agentclientprotocol.com/protocol/v1/overview); [MCP tools specification](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2026-07-28/server/tools.mdx).
4. **Use structured streams where available and validate them.** Pin tested CLI/API versions; retain raw stdout/stderr/events; parse with versioned contracts; test malformed, truncated, interrupted, and resumed runs. Do not mistake “JSON output option” for a stable result contract. OpenCode issues report JSON-output and completion-event problems in specific versions; these are issue reports, not proof of a currently unfixed general defect. [OpenCode issue #31404](https://github.com/anomalyco/opencode/issues/31404), reported against v1.16.2 and marked closed; [issue #42238](https://github.com/anomalyco/opencode/issues/42238), open when checked.
5. **Keep background run control outside the terminal UI.** Persist the launch receipt before dispatch; record whether a run was accepted, rejected, or left in an unknown state if the process dies around submission. Never resend automatically when you cannot prove whether the original prompt was accepted. The local comparison documents durable dispatch receipts/mailbox approaches and why ambiguous submission matters. [Local comparison](<https://github.com/MVPavan/coding-ritual/blob/09cee1bac75cf2ec6c23839ba3f1c069be80b379/docs/research/codebases/comparison-herdr-orca.md>).
6. **Prefer worktree isolation for concurrent writers, with explicit cleanup ownership.** Return the worktree/ref in the result. Preserve user changes and avoid merging automatically unless the caller requests it. Existing products demonstrate worktree-per-agent; they do not prove that a worktree also isolates credentials, network, or permissions. [Claude Squad](https://github.com/smtg-ai/claude-squad); [Uzi](https://github.com/devflowinc/uzi).
7. **Model cost as optional evidence, not an assumed field.** Some harnesses expose token counts or cost in events; others may only return text or bill through a subscription. The envelope should distinguish unavailable, estimated, and provider-reported values. Gemini documents token stats; Copilot cloud agent documents usage through Actions minutes and AI credits. [Gemini CLI](https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/headless.md); [Copilot cloud agent](https://docs.github.com/en/copilot/concepts/agents/cloud-agent/about-cloud-agent).
8. **Treat terminal automation as an adapter fallback, not proof of a completed turn.** The VIA handoff’s Herdr probe reports a silently lost first prompt and a Claude folder-trust dialog; that was a local live probe, not independently replicated here. [VIA handoff](<../../workstreams/handoff.md>). Separately, OpenCode’s issue tracker contains reports of JSON event/output problems in named versions; they are report evidence and must not be generalized without reproduction. [Issue #31404](https://github.com/anomalyco/opencode/issues/31404); [issue #42238](https://github.com/anomalyco/opencode/issues/42238).
