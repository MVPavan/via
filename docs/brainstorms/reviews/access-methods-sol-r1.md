## Findings

1. **BLOCKER — §3, line 211; §6, lines 416–424: OpenCode is presented as a v0 CLI adapter without a workable isolation path.** The existing [OpenCode profile](https://github.com/MVPavan/coding-ritual/blob/09cee1bac75cf2ec6c23839ba3f1c069be80b379/workflow_interpreter/profiles/opencode.py#L1) refuses both spawn and resume: `opencode run` cannot enforce the proposed write bounds. The [handoff](../../workstreams/handoff.md) requires isolation per spawn. “VIA-supplied isolation” is a dependency, but no mechanism is specified. **Fix:** make OpenCode v0 conditional on a defined, verified external sandbox, or remove it from the executable v0 set.

2. **MAJOR — §2, line 189; §5, line 396: “VIA is the permission policy” overstates ACP control.** ACP agents *may* request permission; the protocol does not require every tool action to pass through VIA. OpenCode’s native ACP retains its own built-in tools and permissions. Evidence: [ACP prompt-turn specification](https://agentclientprotocol.com/protocol/v1/prompt-turn), [OpenCode ACP documentation](https://dev.opencode.ai/docs/acp/). **Fix:** say VIA handles requests an agent sends; enforce write and network bounds through verified agent settings or an external sandbox.

3. **MAJOR — §2, line 175; §4.3, lines 304–306; §3, line 216: Factory Droid’s `add_user_message` is counted as mid-turn steer without evidence.** Factory documents it as “Send a turn to the session”; its [RPC documentation](https://docs.factory.ai/droid-exec/overview) does not establish injection into an active turn. **Fix:** mark Droid steer **UNVERIFIED** and probe active-turn timing before recommending RPC specifically for steer.

4. **MAJOR — §2, line 176; §3, line 213; §6, lines 444–445: Pi `abort` alone does not satisfy an end-work cancel verb.** Pi says queued steering and follow-ups continue after `abort`. Evidence: [Pi RPC commands](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/rpc-commands.md). **Fix:** specify queue clearing, abort, and a settled-state check; describe remaining race and process-termination semantics.

5. **MAJOR — §3, line 203: “CLI …; ACP for cancel” implies ACP can cancel a Gemini CLI turn.** ACP `session/cancel` addresses an active ACP session, not a separate `gemini -p` process. The same route ambiguity appears in the Hermes row at line 218. Evidence: [ACP cancellation contract](https://agentclientprotocol.com/protocol/v1/prompt-turn). **Fix:** choose one route for each managed run; advertise ACP cancel only for runs spawned through ACP.

6. **MINOR — §1.1, line 60; §2, line 172: RPC concurrency is generalized too far.** “One server can host many threads” does not describe Pi’s single current RPC session: its commands expose one `get_state` and switch sessions with `new_session`/session selection. Evidence: [Pi RPC commands](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/rpc-commands.md). **Fix:** state concurrency and process ownership per vendor; budget separate Pi processes for simultaneous runs.

**Verdict: REWORK.** The CLI-first direction remains plausible, and the checked SDK language and Codex transport claims held up. The v0 OpenCode dependency and the cancel, steer, and permission claims need correction before this can guide adapter design.
